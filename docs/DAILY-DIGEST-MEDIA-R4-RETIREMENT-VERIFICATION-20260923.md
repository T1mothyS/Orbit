## 媒体引用与备份边界

应用使用内容哈希作为媒体文件名和对象键；不同文章或产物可保留不同媒体 ID，却引用相同字节。`prepareDigestMedia` 先写本地独立镜像，再上传测试 R2；网页与邮件 HTML 引用对象公开地址。账号加密备份从该账号的 V2 产物收集文件名与字节，校验哈希后恢复本地镜像；全站备份另包含日报媒体目录。`restoreDigestObjects` 从本地镜像上传对象并读回核对哈希。当前没有针对 V2 产物的独立媒体下架与引用替换接口，历史产物保持冻结，因此不能仅按对象键删除共享图片。

隔离服务的持久化数据库只读查询了 `publication.media` 元数据，没有导出正文或个人输入：审计时 10 个 Shadow 产物含 9 条媒体引用、4 个不同对象键，其中 3 个键被重复引用，单键最多 4 条引用。本卡新建并删除的测试键不在这些产物中。这证明现存对象确有共享引用；计数仅代表这次隔离数据库快照，不能外推到正式账号。

相关合成回归 `server/digest-v2.test.ts` 和 `server/core.test.ts` 合计 37/37 通过，其中覆盖同字节多媒体 ID、账号备份中媒体字节、账号恢复、损坏备份拒绝，以及全站媒体目录恢复。这些测试不读取或覆盖真实账号备份。

## CDN 清除未通过

Cloudflare 测试桶设置显示只有公开开发地址，没有连接自定义域名。Cloudflare [R2 公共桶文档](https://developers.cloudflare.com/r2/buckets/public-buckets/)说明 `r2.dev` 不提供缓存功能；因此本次 404 仅证明对象删除及开发地址不可读，**不构成 CDN 失效证据**。[R2 一致性说明](https://developers.cloudflare.com/r2/reference/consistency/)指出，自定义域名启用缓存时，删除对象后旧内容可能继续从缓存返回，需要清除缓存。[缓存清除文档](https://developers.cloudflare.com/cache/how-to/purge-cache/)还说明清除请求成功只表示请求被接收，需再次读取目标 URL 验证。

后续要完成 CDN 项，需有隔离的测试自定义域名和可确认的缓存命中；只对本卡模式的新建测试 URL 执行对象删除及单文件清除，并观察清除前后读取。正式媒体下架另需冻结新发布、逐账号核对所有历史引用、保留私有备份、处理正文引用，再删除对象和清除对应 CDN URL。当前没有此完整流程的端到端证据，不能宣布真实媒体下架完成。
