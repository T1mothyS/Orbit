## 结论

技术方向总体合理：在既有 Cloud 链路上演进，保留 Local/V1，使用结构化合同、确定性渲染、隔离 Shadow、账号边界、版本化事实和现有数据库。没有证据支持重写架构或另加数据库。当前主要偏离是**验收和实现优先级偏向媒体、样式与基础设施，而内容是否有价值缺少可判定的基线**。

不需要再收集满七天才继续。9/26 的路线图已取消这一硬前置，本次不是第一次取消；剩余问题是 D03→D02→D04 串行关系仍把媒体外部条件变成后续开发阻塞。此次把内容评审放到最前，并把本地开发、媒体生命周期与生产放行分开。减少等待不意味着宣布未验项目通过。

## 审计发现

### 1. 高优先级：结构通过与内容通过混在了验收目标中

`server/digest-v2-contract.ts` 的 `validateDigestV2` 校验字段、URL 形状、ID 引用和个人输入覆盖；`verification=verified` 只要求存在证据引用，校验器不会访问来源或判断正文是否得到证据支持。`executive_signals` 与 `what_matters_next` 仍是文本数组，不具有逐项证据关联。不能把 `0 errors/0 warnings` 称为新闻内容验收通过。

本次直接调用纯函数的合成探针结果（无网络、无保存）：

| 输入 | 实际结果 | 含义 |
| --- | --- | --- |
| 空新闻、空证据、成功但为空的个人输入 | `valid=true`，无 warning | 零新闻是合法格式，无法证明检索充分 |
| 截点 `2026-09-27T03:00:00Z`，证据发表时间 `2026-10-01T00:00:00Z`，新闻标 verified | `valid=true`，无 warning | 没有来源时间与截点的一致性校验 |
| 同一标题/摘要/证据复制一条，只换新闻 ID | `valid=true`，无 warning | ID 去重不是语义/事件去重 |
| 完整字段、超过 20 字的中文摘要但无加粗 | `valid=false`，`EMPHASIS_REQUIRED` | 当前样式是硬闸门，强于上述内容诊断 |

这些是已复现的校验边界，不证明某一真实日报已经含未来信息或重复新闻。相应修复进入 D02 下一轮候选，不在本次修改。来源支持、选题和遗漏先用人工可复核表衡量；时间一致性可以独立做机械校验，不能指望一次校验器升级解决事实判断。

### 2. 高优先级：有新闻/空新闻的产品验收没有闭环

当前有逐条配图统计和运行回执，但缺少同等明确的检索范围、候选排除理由、重大遗漏、重复与个人相关性的通过条件。9/27 空新闻早版的记录只支持“生成并展示了空新闻结果”，不能独立证明当时没有值得报道的新闻。本轮未重新检索或阅读私人产物，故对该期选题好坏保持无法确认。

路线图已补 D02 评审表及失败条件。旧 V2 同截点对照是辅助证据，不是金标准。先利用已有样本定位问题，不能为凑有图日期而挑题、补旧新闻或重复同日生成。

### 3. 中优先级：媒体安全是真缺口，但不应阻塞所有开发

`digestArtifactView` 从冻结 publication 重新渲染，当前没有真实媒体的可审计显示降级入口；共享对象直接删除会留下失效引用。这个问题仍约束真实下架和对应生产放行，不因重排计划而移除。`tmp/` 生命周期、快照七天保留和收集七份日报是不同机制。

D03 继续做引用降级、恢复和跨日期展示证据；七日自动到期保留待观察，不要求内容改进和单独授权的本地 V3 闭环一起等待。没有改变当前逐条配图需求或许可规则。

### 4. 中优先级：V3 存储领先于可见收益，下一步必须接最小闭环

`digest-v3-store.ts` 使用账号复合外键、事务、不可变记录和当前修订冲突检查；测试实际覆盖迁移、持久化失败回退、账号隔离与旧备份保护，路径合理。当前 MCP/HTTP 尚未暴露 V3，存储接口的 TypeScript 类型和 SQLite 约束不等于完整外部输入校验，Core 合同也明确后续补业务校验。

D07 应先证明一条来源如何成为事件版本，再如何在隔离日报中减少重复/解释变化；严格写入校验和幂等必须随闭环落地，不直接公开内部存储方法。D08–D10 继续负责保守匹配、纠正、冻结引用和评测；D11–D15 暂不扩展实施。D04 可作“允许本地开发但不允许生产”的范围决定，仍需用户单独实施授权。

### 5. 低优先级：可维护性适合局部演进，暂不扩大重构

合同/服务/媒体/渲染/存储已分层，沿用 sql.js 和既有通知/备份避免了多套基础设施。局部存在密集单行语句、手写 schema、JSON 反序列化和历史 generation 分支，后续修改这些路径时应保持回归；没有必要为了本次审计全面拆分或替换框架。结构化测试覆盖可读写边界，不能替代真实内容和 UI 验收。

## 修订后的行动顺序

1. **先做内容基线**：复核已有普通有新闻、空新闻、失败/修订样本，输出逐项缺陷与合格样稿判据；不等待新日期，历史不足处标未知。
2. **再做定向改进**：按失败项调整检索/筛选/摘要策略，候选工程项为来源时间诊断、重复候选诊断、有界检索记录和样式提示降级；实施另行授权。
3. **独立收口证据**：D03 媒体引用安全、D02 真实个人输入和跨日期集成继续各自验收；七日到期只影响对应生命周期结论。
4. **分层作决定**：D04 分开本地 D07、继续隔离和生产切换，不能把允许开发写成第一阶段整体通过。V3 有最小可见收益后再按原序列扩大范围。

完整结束条件只维护在 [路线图](ROADMAP.md#d02-内容质量闸门2026-09-27-审计修订)，[测试矩阵](TEST-MATRIX.md#daily-digest-内容与运行验收分层) 指明证据层。本审计为日期快照，不替代这两个持续文档。
