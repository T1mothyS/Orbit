### 顺序与验收闸门

- 当前优先顺序改为 **D02 内容质量基线 → 定向改进/回放 → D04 分层决策**；D03 独立收口，不阻塞内容诊断。D05/D06 保留已完成的本地成果。D04 可在 D02 已列明内容缺陷和 V3 能解决的具体问题、D01/D06 隔离与恢复回归通过、公开写入校验方案明确后，批准单独授权的 D07 本地最小闭环；不必等待真实邮件、第二个有图日期或七日到期，但不得带入生产或自动扩大到 D08–D15。
- 截至本次审计，本机记录有 9/22、9/23、9/26、9/27 四个真实日期；改进后 9/26 有 5 条新闻（3 张资料照片、2 张插画），9/27 10:57 早版为零新闻。后者只证明空态和输入处理，不证明当天无值得报道的新闻，也不是第二个有图日期。媒体测试对象恢复/CDN 与五张真实图备份有历史证据；真实引用降级/下架、第二个有图日期、真实邮箱客户端仍未验。这些时点记录本轮未远程复验。
- “七类故障样本”“七个真实日报日期”“tmp/ 七天自动到期”是三个不同指标。七类保留固定回归；七个日期取消为统一前置，可作为可选稳定性观察；tmp 到期仍需真实时间才能声称验证通过，但只约束该生命周期结论。无需凑天数，也不把两天改成内容质量的替代门槛。
- D07–D10、D11–D12、D13–D15 分别形成 V3、Scheduled Events、Research/Thesis/Radar/Flash 的实施与验收序列。每张卡内部先记录当前最小可验证步骤；同卡可以跨会话和多个本地提交，不再因接口、UI、整合检查各建一张计划卡。
- 真实运行和外部依赖与代码检查分开：固定样本验证规则，真实 Shadow 验数据/时效/稳定性，恢复演练验可逆性，真实邮件与生产切换单独验最终行为。任何关键项受限时不把该阶段标成整体完成。V3 的错误合并优先处理，不通过扩大自动匹配掩盖。
- 每次交接记录卡号、已达到的结束条件、未达条件、证据位置、Git/版本、下一条最小操作及外部副作用。文档或证据变更无应用行为变化时不升应用版本；代码变更按项目规则测试、构建、检查 diff 并同步版本。卡片数不等于会话数或工期承诺。

### D02 内容质量闸门（2026-09-27 审计修订）

先形成一份逐条评审表，不新增服务或数据库。每份记录固定日期/截点、输入快照或可追溯摘要、实际 Prompt/合同版本、检索范围及失败、候选来源、入选/排除理由、预期与实际差异和评审结论；私人输入只保存在原安全边界，提交文档仅写脱敏结论。已有证据不足就标“无法确认”，不把今天新搜索的结果冒充过去截点已知信息。

| 维度 | 通过条件与失败处理 |
| --- | --- |
| 选题与相关性 | 先明确用户关注范围和何为重要；逐条说明新事实、为什么值得读、后续关注点。不按栏目凑数，不为有许可图片而改变选题。用户对代表性样稿的可用性评价须单列，未取得时不能代签通过。 |
| 来源与时间 | 关键事实能回到具体来源；事实/推断分开，发表/发生/获取/截点分开。已知发表时间晚于截点不能当成本期已知事实；未知时间如实保留。自动格式校验不等于事实核实。 |
| 遗漏与重复 | 成功个人输入逐项覆盖且摘要含义正确；对限定的候选来源清单核对重大漏项，同事件转载不重复占篇幅，后续进展说明新增事实。旧 V2 不是正确答案，不要求全网无遗漏。 |
| 空新闻与失败 | 空数组合法，但“无重要新闻”需要检索范围/时间窗/候选排除记录支持；未检索、来源失败、仅查少量来源不能替代该结论。早版不得冒充全天。 |
| 阅读与图片 | 重点清楚、摘要可读、引用可查；每条配图继续遵守真实图/标注插画/缺图合同，缺图和失败如实记录。图片覆盖不能替代内容质量。 |

评审样本出现事实错误、已知未来来源、重大遗漏、无依据的“无变化”或重复充数，相关内容项即失败，先修正并回放；不得平均打分冲抵。普通有新闻、空新闻、失败/修订三类可先复用已有样本；回放改善证明规则改善，跨日期真实运行另证集成。每个失败项必须对应最小修复、验收样本和完成条件。

下一轮实现候选（本次只规划）：对已知来源时间与截点做一致性检查；对重复候选给出可解释诊断并人工区分同事件新进展；让生成过程留存有界的检索/选题依据。长句加粗当前仍是硬错误，后续优先评估改为编辑提示，避免样式重试压过内容修正；修改合同前保持现有行为，不在文档中假称已修复。

- 更精确的知识来源引用、段落级摘要和跨项目阅读入口。
- 有实际数据证明普通搜索不足后，再评估 embedding、hybrid search、reranker 和 RAG。

# Won't Do

- Google Docs 式实时协作、CRDT 和多人实时编辑。
- 本地 Markdown 与服务器正文双向同步。
- NoteBoard 或 Daily Report 自动单向生成 Knowledge Fragment；两者继续在各自本地流程维护并上传到各自目标系统。
- 向量数据库、RAG 或自动 AI 覆盖原知识，直到普通知识库稳定且有真实使用需求。
- 自动网页抓取、浏览器插件、复杂富文本编辑器、公共知识社区和无限层级文件夹。
- 为了形式一次性重写整个 server/index.ts 或建立复杂全文搜索服务。
