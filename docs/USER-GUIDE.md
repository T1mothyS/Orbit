## 账户与安全
<!-- product-help: user -->

从头像菜单选择“设置 → 账户与安全”，或直接选择“账户与头像”。这里可以查看登录信息、上传或恢复头像、修改密码、退出当前登录；个人资料位于同分类的二级 tab，也可从头像菜单直接进入。设置内外的右上角共用头像菜单。

### 修改密码

修改密码时填写当前密码、新密码和确认值，再选择“更新并重新登录”。新密码至少 8 位、最多 72 个 UTF-8 字节（中文等字符占用多个字节）。成功后所有设备上的 Orbit 登录都会失效，请使用新密码重新登录；Cloud、日报/知识库令牌和 ChatGPT 授权保留。普通“退出当前登录”只退出本机，并清空本机未发送的对话草稿。

密码不会保存为设置草稿，取消或离开页面即清空。如果提示修改结果暂时无法确认，请先重新登录检查密码，不要把网络中断视为一定没有修改。头像上传支持 JPEG、PNG、WebP，最大 5 MB；无头像时显示默认标识。

## 对话、提醒与统计
<!-- product-help: user -->

Android 安装与配置见 [构建说明](../android/README.md)。常规入口保留 Android 手机提醒独立开关、通知权限、设备注册与投递状态；开关默认关闭。本地一分钟与 FCM 测试仅在显式开启开发者工具的 debug 构建展示，普通 debug 和 release 均不展示测试面板。正式提醒仍走 FCM，本地试验不承担正式运行依赖。

Android 正式提醒需要通知权限、当前账号的设备绑定和可达的推送网络；服务端接受发送不代表手机已经显示。开发者试验的构建与排错步骤仅维护在 Android 构建说明。

默认入口 /assistant。Orbit 主对话置顶并保留旧历史；普通会话行内编辑/删除，事项可单独开聊。生成期间可继续输入、排队和操作卡片；等待区域用小型旋转图标和引号展示俏皮话，每条随机停留2–5秒再换句，作为缓解等待的趣味文字。真实步骤、耗时和取消独立显示，终态后停止；减少动态效果时不旋转、不淡变。AI 修改仍需确认计划。

对话顶部的橡皮图标清空当前对话，操作前仍需确认；纸张图标打开记事板，右上角数字表示未完成记事数。手机日报页的筛选图标打开原有筛选面板，应用前不会更改当前条件。

手机设置首页按分类显示图标和用途说明，点入分类后再切换对应页签；具体设置项的帮助方式保持原样。点击顶栏放大镜会在同一行展开搜索，暂时收起Orbit文字，关闭或按Escape可收回。使用指南每节标题右侧的箭头进入对应页面，“询问AI”只把问题补进原会话草稿，保留原文字和图片，需要你检查后发送。

### 产品帮助与运行查询

头像菜单的“使用指南”打开 `/help`，也可阅读 [快速上手](QUICK-START.md)。“询问 AI”仅把固定问题追加到原会话的未发送草稿，已有文字和图片保留；不会自动发送。设置已统一到九类独立页面；日报的“个性化”和“接收与邮件”页签保留普通草稿，敏感输入离开页签/分类后清空。资料/日报版本冲突保留草稿，需重新加载核对后才能继续保存；重新加载会明确提示丢弃两处未保存修改。

直接问“日报怎么修改关注行业？”“知识库怎么设置？”“当前 Orbit 是哪个版本？”或“今天日报为什么没生成？”。产品说明来自随构建生成的现有规范文档索引，与个人文章检索和系统运行记录分开。设置回复提供“打开日报设置”等可点击入口，刷新聊天仍可使用；Web 与 Android 共用入口映射。

版本、健康和自己的日报/提醒/聊天任务可查询。管理员另可查部署失败阶段、脱敏错误及后台任务时间；普通账号不能读其他账号或全站错误。日报按输入准备、校验、媒体、保存与通知记录解释；没有外部 Work 调度/模型回执时显示未观测，不猜测失败原因。服务端发送接受不表示本次手机展示或邮件收件箱已到达。服务器未收到知识库发布请求，也无法判断本地加工或排除原因。

只读助手不能重启、重新部署、重跑、补发、删除、修改配置或清日志。历史运行证据可能过期；没有部署采集配置或最新快照时会明确说明未观测/过期。运维接入和保留规则见 [部署路径](DEPLOYMENT-PATHS.md#受控运维记录与保留)。

待创建条目的“编辑”右侧提供“删除”：点击后只移除该草稿条目，刷新后保持结果；删除最后一项会取消整份草稿。保存、删除和确认执行不能同时进行。纯新建计划不展示作为参考读取的已有日程；修改或删除计划仅展示涉及的目标，查询及执行结果仍显示对应卡片。

设置统一为账户与安全、通知与提醒、AI 与模型、日报、知识库、同步与集成、数据与备份、高级、使用统计九类。桌面左分类、右当前页；手机先选分类，再进入子页。知识库手机阅读的控制条紧贴顶部，返回仅显示箭头，章节按钮可以横向滚动。

右上角“清空当前对话”和会话行的垃圾桶均采用两次点击：第一次变对勾，第二次执行。5 秒未确认、点击其他区域、Escape、切换会话或关闭历史菜单会取消确认。清空保留会话名称和未发送文字、记事图片草稿，但删除聊天消息、聊天附件、历史请求和待确认计划关联；普通会话删除仍保留已创建的日程与记事，固定 Orbit 主会话只能清理历史。排队/生成时先取消请求，附件上传或其他写操作结束后再清理。取消成功的请求不再占据聊天底部；失败和中断保留重试。

站内通知与主动聊天提醒共用“设置 → 通知 → 通知渠道”中的站内开关。普通明确时间事项默认提前 15 分钟，逐事项规则、稍后与次日提醒保留；周期遵守原规则。后台扫描是否启用以运行状态为准；保存个人偏好不会自动启动后台服务。卡片显示来源、时间和对象，支持查看、就此继续聊及适用的完成/延后；事项变化后会阻止旧操作。投递、已读和事项完成是不同状态，历史已发送通知不会批量导入聊天。

输入框下方的 `+` 菜单包含模型、附件、历史、新对话、通知设置及自动检索知识库。自动检索默认关闭，账号偏好保留，开启后可点击输入框上方标签关闭。明确提到知识库仍可检索。聊天草稿按账号/对话保存在本浏览器会话；设置搜索、全局搜索和 AI 设置入口使用同一定位索引，打开统一设置页面并定位；不存在或无权访问的项明确提示。AI 不会自动修改设置，也不会读取密钥值。

头像菜单按分隔线分组：设置、使用统计、主题；邮箱导入、研究与观点、Tools、项目成长、使用指南及管理员入口；退出。设置顶部不再重复显示项目成长、Tools 和统计快捷入口，项目成长页不再提供统计跳转。底部显示版本信息。邮箱导入仍兼容旧链接；设置、统计、邮箱导入、经历、研究、Tools、项目成长和指南的左上箭头统一返回今日。知识条目、日报正文等内部详情继续返回所属列表。账户与个人资料从“设置 → 账户与安全”进入，原链接继续有效。桌面设置搜索居中显示，手机仍在顶栏内展开。账户中可上传/更换/移除 JPEG、PNG、WebP 头像，最大 5 MB，服务端压缩为 256px WebP 并清除 EXIF。默认头像为邮箱首字母。记事正文中的 HTTP/HTTPS、Markdown、站内链接和 `ippure.com` 一类裸域名可以直接打开；裸域名默认 HTTPS，显示、编辑及复制文字保持原样，邮箱和常见文件名不转换。点击链接不会进入编辑；普通正文与编辑按钮继续编辑。内部对象、登录回跳与浏览器前进后退保留定位；无权限或失效对象显示提示。

### 个人活动报告

从头像菜单的“使用统计”进入；个人菜单中的邮箱只用于显示账号。统计页左上箭头返回今日，周报配置仍在设置的通知分区。保留周/月/年，箭头切换相邻周期，重置图标回到当前所选周期；“自定义”展开当前页时间浮层，设备时区输入，点击应用后生效，页面同时显示账号时区和 UTC 起止。默认事项/日报来源筛选与已保存报告位于“设置 → 使用统计”；默认筛选只影响实时报告，不改变自动周报和历史快照。开始包含、结束不包含。报告依次展示概览、执行趋势、节律与完成度、积压/逾期、知识、AI 协作和洞察明细。每项可展开同口径原始对象；日报链接定位到具体日期，周期链接定位到具体实例。

- 本期安排完成率：当前已完成的本期安排 / 本期按安排日期落入范围的事项及周期实例。无安排时没有百分比。
- 本期实际完成：有效完成记录的完成时间落入范围，每个事项或周期实例一次；撤销完成不计。无日期待办纳入新增、完成和当前积压。
- 积压、逾期、长期未处理是标注快照时间的当前状态；长期未处理是创建超过七天的无日期待办。改期只计真实记录的日期变更，不猜过去次数。
- 创建至完成间隔仅使用可靠创建/完成时间的普通事项样本，不是专注时长。分类是新增事项数量分布，不是精力/时间占比。
- AI 指标计确认执行的创建/修改、成功且有结果的工具步骤、成功记事优化、实际知识引用及从提醒完成。生成建议不计采纳，不推断 AI 导致完成。
- 热图计事项创建、有效完成、用户聊天和记事创建，系统通知不计用户活动。周期用户选择的完成日期用于完成统计，热图用实际记录创建时刻。
- 来源、改期、优化及 AI 确认从页面标明的采集起点记录，历史缺失显示未记录；部分采集不能按完整周期比较。知识阅读/引用另有采集起点。

点击“生成洞察”才调用当前账号选用的 Provider/模型；只发送有界统计与必要对象摘要，不提供写入工具。报告与洞察绑定固定快照，数据变化提示重新生成。模型失败保留事实和重试入口。

### Orbit Weekly 与其他总结的边界

自动个人周报默认关闭，在通知设置开启；默认账号时区周日 20:00，星期和时间可改。稳定计划按相邻截止点覆盖七个本地日；改动发送时点的首次范围接续最近实际截止点，长期停服只补最近一个遗漏周期。后台关闭会显示提示，可手动生成。报告保存概览、主要执行明细、节律、积压、知识、AI 和下一周期到期对象；网页、邮件和聊天引用同一个报告 ID/快照。

“预览并发送周报”展示当前内容，点击确认后才进入已开启的邮件/站内渠道；相同账号/报告/渠道去重。邮件分别显示排队、失败、SMTP accepted，不能推断收件箱到达。模型不可用仍能发送事实版，自动周报不需要授权 AI 修改业务数据。

当前只提供有界历史摘录与显式知识检索，通用长期记忆尚未实现；每日行动提醒概括当天安排；情报日报使用独立 Local/Cloud 发布链路；个人周报复盘自身活动。这四项没有共用发布合同。

账号加密备份包含头像、活动事件、报告快照和周报偏好；旧备份继续兼容。恢复后自动周报保持关闭，不重新投递旧通知。同账号保留可验证引用；跨账号保留历史事件/快照并停用原账号对象链接，界面提示重新从恢复后的对象生成报告。清空/删除账号会清理相应记录。

## 4. 邮件系统配置

### 4.1 发件邮箱与收件邮箱不是一回事

| 类型 | 配置位置 | 说明 |
| --- | --- | --- |
| 官方发件邮箱 | 服务器 `.env` | 固定为 `aicalendarofficial@163.com`，所有验证码和提醒都从该账号发出 |
| SMTP 授权码 | 服务器 `.env` | 只由管理员配置，用户看不到 |
| 用户提醒收件邮箱 | 页面右上角“设置” | 每个账号独立保存，可以与注册邮箱不同 |
| 默认收件邮箱 | 用户注册资料 | 用户未填写提醒邮箱时使用注册邮箱 |

因此项目不再使用 `REMINDER_RECIPIENT_EMAIL`。这个全局变量会让所有用户共用同一个收件地址，不符合多用户产品逻辑，也容易把提醒发错人。

### 4.2 163 SMTP 必填配置

```dotenv
SMTP_HOST=smtp.163.com
SMTP_PORT=465
SMTP_USER=aicalendarofficial@163.com
SMTP_PASS=这里填写客户端授权码
```

`SMTP_PASS` 不是 163 网页登录密码，而是邮箱开启 SMTP 服务后生成的客户端授权码。

获取步骤：

1. 登录 `aicalendarofficial@163.com` 的网页版邮箱。
2. 打开邮箱设置，找到 POP3/SMTP/IMAP 或“客户端授权密码”相关设置。
3. 开启 SMTP 服务；第三阶段需要邮箱导入时再同时开启 IMAP。
4. 按页面要求完成安全验证并生成客户端授权码。
5. 只把授权码填写到服务器 `.env` 的 `SMTP_PASS`。
6. 重启本地 Node.js 服务或服务器上的 PM2 服务。

不要把授权码发到聊天、截图、Git 提交或 README 中。

### 4.3 SMTP TLS 报错排查

报错：

```text
Client network socket disconnected before secure TLS connection was established
```

表示程序在完成 TLS 安全连接前，连接就被断开了。当前项目之前的实际问题是：`.env` 使用了 Gmail 的 `SMTP_HOST/SMTP_USER`，而代码发件人固定为 163 官方邮箱，两套配置不一致。

排查顺序：

1. 确认 `SMTP_HOST=smtp.163.com`。
2. 确认 `SMTP_PORT=465`。
3. 确认 `SMTP_USER=aicalendarofficial@163.com`。
4. 确认 `SMTP_PASS` 是该 163 账号新生成的客户端授权码。
5. 修改后重启服务。
6. 登录页面，在右上角“设置”中填写当前用户的提醒邮箱，再发送测试邮件。

常见错误对照：

| 错误 | 一般含义 | 处理方式 |
| --- | --- | --- |
| `EAUTH` / authentication failed | 账号或授权码错误 | 重新生成 163 客户端授权码，确认不是网页登录密码 |
| TLS/socket disconnected | 主机、端口、TLS 或网络路径错误 | 核对 163 主机和 465 端口，检查服务器出站网络 |
| timeout | 服务器无法及时连接 SMTP | 检查云服务器防火墙、运营商限制和 DNS |
| 页面提示没有收件邮箱 | 当前用户没有注册邮箱或提醒邮箱 | 在右上角“设置”中保存提醒邮箱 |

### 4.4 测试邮件

1. 启动前后端。
2. 登录一个用户账号。
3. 打开右上角“设置”。
4. 填写并保存“提醒收件邮箱”。
5. 如需验证通知邮件通道，在“周期提醒”页面使用“测试邮件”；设置中的“测试读取”仅检查 QQ 未读摘要，日程摘要的实际投递需另行核对。
6. 检查页面反馈、后端终端日志、收件箱和垃圾邮件箱。

测试邮件只验证发件链路，不会把用户收件邮箱写入 `.env`。

## 5. `.env` 与 `.env.example`

`.env.example` 不是运行时配置，但它非常有用，应该保留并提交到 Git。

| 文件 | 是否被程序读取 | 是否提交 Git | 用途 |
| --- | --- | --- | --- |
| `.env` | 是 | 否 | 当前机器的真实密钥、授权码、邀请码和部署地址 |
| `.env.example` | 否 | 是 | 安全的配置模板，说明项目需要哪些变量 |
| `.gitignore` | Git 使用 | 是 | 防止 `.env`、数据库、附件和构建产物被提交 |

新机器部署时先复制模板：

```powershell
Copy-Item .env.example .env
```

Linux 服务器上使用：

```bash
cp .env.example .env
```

然后只编辑新生成的 `.env`。如果未来增加新的环境变量，应同时在 `.env.example` 中添加不含秘密的占位项和说明。

## 6. 环境变量说明

### 6.1 认证与账号

| 变量 | 必需 | 说明 |
| --- | --- | --- |
| `JWT_SECRET` | 是 | JWT 签名密钥，生产环境必须使用随机长字符串 |
| `EMAIL_CODE_PEPPER` | 建议 | 验证码 HMAC 独立密钥；留空时回退到 `JWT_SECRET` |
| `ADMIN_INVITE_CODE` | 首次初始化时 | 数据库尚无管理员邀请码记录时的迁移期引导值；初始化后以数据库为准 |
| `USER_INVITE_CODE` | 首次初始化时 | 数据库尚无普通用户邀请码记录时的迁移期引导值；初始化后以数据库为准 |

### 6.2 官方邮件

| 变量 | 必需 | 说明 |
| --- | --- | --- |
| `SMTP_HOST` | 是 | 固定使用 `smtp.163.com` |

### 6.3 用户 QQ 邮箱摘要（可选）

| 变量 | 必需 | 说明 |

| `MAIL_CREDENTIALS_ENCRYPTION_KEY` | 使用网页 QQ 邮箱配置时必需 | 独立随机长密钥；不能与 `JWT_SECRET` 或 `BACKUP_ENCRYPTION_KEY` 共用 |

网页设置中的 QQ 邮箱固定使用 `imap.qq.com:993` TLS 连接。服务端只读取未读邮件摘要，不保存邮件正文，不标记已读；V2 通过日报只读令牌调用 `/api/integrations/daily-report/mail`。未配置该变量时，其他登录、日历、提醒和日报功能仍可运行，但不能保存用户 QQ 邮箱配置。

| 变量 | 必需 | 说明 |

## 9. 主要页面与使用流程
<!-- product-help: user -->

### 日程与无日期待办

从“日程”创建或编辑事项，核对标题、开始和结束时间；全天事项使用日期，无固定日期的待办保存在挂起区。也可以在 Orbit 对话描述安排，检查 AI 草稿的时间、类型和对象后点击确认；确认前不会写入正式日程。修改已有事项时先打开目标核对，保存失败保留表单，结果未知时先重新加载核对，不重复创建。

### 查询知识库与管理条目

从“知识库”阅读文章，使用全局搜索、类型或状态筛选定位条目。普通文章由本地加工与发布流程维护，网页提供阅读、评论、版本与导出；“记录经历”有独立的复盘、预览、确认和归档流程。只有明确提及“知识库”或开启自动检索时，普通对话才会检索当前账号允许的文章。个人资料在账户设置，日报关注项在日报设置；“设置 → 知识库”负责发布接入与全库导出。

### 提醒与通知排查

在“设置 → 通知与提醒”核对收件邮箱、邮件/站内/浏览器渠道、提醒时间及免打扰。Android 另需通知权限和设备绑定。保存设置不立即发信或补发；先看对应事项、通知与运行记录，区分未到时间、未入队、失败和发送接受。邮件发送接受不等于收件箱到达，Android 发送接受也不等于手机显示；没有观测证据时保持未观测，不推测外部网络或设备状态。

### 9.1 今日行动中心

登录后默认进入 Orbit 对话；从导航进入 `/today`，按以下优先级突出一个“下一步”：

1. 正在进行或两小时内开始的日程。
2. 高优先级逾期事项。
3. 其他逾期事项。
4. 今日到期事项。
5. 临期事项。

### 9.2 周期事务

进入“周期提醒”，选择模板、填写周期和提醒时间。周期到期后可以标记完成并保存证明。系统没有跳过按钮；逾期任务仍可完成，完成后按对应 `advancePolicy` 生成下一周期。

### 9.3 用户提醒邮箱

进入右上角“设置”：

1. 填写自己的提醒收件邮箱。
2. 设置邮件、站内、浏览器通知开关。
3. 可设置提醒时间和免打扰时段。
4. 保存后可在“周期提醒”页面使用“测试邮件”核对通知邮箱是否收到测试信；每日提醒和日报仍按各自任务状态与实际收件结果核对。

这些设置按登录用户保存，不会修改官方发件账号，也不会影响其他用户。

设置使用九类独立页面，桌面左侧分类、右侧正文，手机从设置首页进入分类。普通未保存草稿在分类间保留，离开设置前会提示；密码、API Key、邮箱授权码和一次性令牌在离开对应分类或页签后清空。每日提醒和日报邮件开关立即保存；通知渠道及免打扰使用“保存通知设置”。

### 9.4 完成证明

完成待办或周期事务时可添加：

- 完成时间。
- 备注。
- 金额（内部以整数分保存，默认 CNY）。
- 账单日期。
- JPEG、PNG、WebP 或 PDF 附件。

单文件最大 10MB，每次完成最多 5 个附件，每位用户默认总配额 500MB。附件只能通过鉴权接口访问。

### 9.5 智能导入

智能导入接受自然语言或最多 3 张图片，每张最大 8MB。AI 首先生成草稿并标注低置信度字段；只有用户检查并确认后，系统才创建日程或周期事务。

邮箱导入的设置和待确认草稿分别显示读取状态。读取失败会保留已加载内容并提供“重新读取”，不会把错误当成没有草稿；设置尚未读到时，失败提示会替代一直等待的占位。重读页面不检查收件箱、不发送邮件，也不确认草稿。

### 9.6 常驻地、天气与普通问答

在“设置”中搜索并确认常驻城市/区县后，AI 助手可回答今天、明天及未来天气；地点和天气来自 Open-Meteo，网络失败时会明确提示不可用，不会编造数据。非日程问题走普通问答，日程写入仍必须经过用户确认。

### 9.7 日报、导出与邮件联动

从“日报”进入 `/reports`，按日期阅读当前账号保存的日报；同日 Local 与 Cloud 可以切换，候选稿和隔离预览保持非正式标识。邮件简报覆盖有价值的信息，邮件待办只列需要行动的内容。正文、图片与来源以当次发布结果为准，普通阅读不会重新下载或补图。

在“设置 → 日报 → 接收与邮件”分别配置来源接收和日报邮件。每日摘要与通知渠道是其他独立设置；保存偏好不会立即生成、发布或补发。日报详情页可确认后手动重新发送当前日报；排队、发送接受和收件箱到达分别核对，不能互相替代。

“设置 → 数据与备份”提供当前账号的 JSON、CSV 和加密备份；“设置 → 日报”管理独立接入令牌与邮件摘要接入。一次性令牌只在生成时显示，离开对应页面后清空，不会进入普通草稿。Local/Cloud 发布、内容完整性及媒体规则的唯一技术合同见 [Cloud 日报](CHATGPT-WORK-CLOUD.md)，不从旧任务名称或旧运行时间判断当前自动化状态。

### 9.8 在网页修改个人资料与日报偏好

进入“设置 → 账户与安全 → 个人资料”编辑个人背景与表达偏好；进入“设置 → 日报 → 个性化”编辑阅读偏好、近期兴趣和关注行业、公司、股票。旧 `/library/preferences` 链接仅作为兼容入口，知识库设置不再编辑日报偏好。五组表单可维护个人背景、回答偏好、阅读与证据要求、近期兴趣、行业/公司/股票以及研究框架，无需制作或上传配置文件。展开复杂分组后增删列表，在关注对象下选择“编辑研究框架”或“建立研究框架”。

修改后点击“保存”；“取消”恢复最近读取的版本。离开未保存页面会提醒，草稿仅保留在当前页面内存，刷新或关闭后不会自动恢复。保存失败仍保留草稿；若资料已在另一页面更新，先重新加载并核对再修改。遇到“输入不完整”，按提示补齐或精简研究内容；资料读取损坏时先通过备份恢复，不用空内容覆盖。

两处入口使用同一账号、同一份资料，下一次 Cloud 日报读取生效。保存不启动日报、不发邮件、不改历史和正式研究观点；本地日报和独立 Shadow 不自动同步。资料时区不改变实际任务时间。知识库导出、发布令牌和日报接收开关可从页面底部链接进入原设置。更多边界见 [知识库说明](LIBRARY.md#个人资料与日报偏好)。

## 11. 备份与恢复
<!-- product-help: user -->

用户备份文件扩展名为 `.aicalendar-backup`，使用口令派生密钥并加密。导出内容包含个人日历、周期事务、AI 记事（包括图片及顺序、当前优化状态、累计次数和正文版本）、完成记录、附件、日报、通知偏好和确认后的 AI 导入记录，不包含密码、角色、JWT、SMTP 凭据和 AI API Key。缺图会明确报告部分恢复。旧备份仍可合并；目标账号已有图文记事时，缺少图片关联的旧备份不能替换，以免丢失现有图片。CSV 导出不包含 AI 记事。

恢复前先使用“检查备份”查看版本、数量和冲突，再选择：

- 合并：仅导入不存在的数据，冲突保留当前数据。
- 替换：先备份当前用户数据，再替换该用户的个人数据。

全站恢复属于高风险管理操作，必须进入维护模式并先生成恢复前快照；管理员全站快照会同时保存用户附件和 `data/daily-report-media/` 日报图片。阿里云 OSS 应使用私有 Bucket、阻止公共访问、同地域内网 Endpoint 和最小权限 RAM 用户。

## 13. 常见问题

### 留住旅行或其他经历
<!-- product-help: user -->

进入“知识库 → 记录经历”，从记得的事情开始说。通常只有一到三次简短追问；也可以直接整理、跳过问题，或在模型不可用时按原话整理。照片最多三张，只用于回忆，不交给 AI。时间可以模糊，评分无需填写。

记不清的地点名称等客观信息可以请求联网核查，候选结果和来源会单独展示；确认符合当时经历后才用于记录。整理完成后修改保存预览，点击“确认保存经历”才进入正式知识库。离开后可从未完成复盘继续；详情中的原始问答默认折叠，可继续编辑、归档和恢复。

单条“导出完整经历”及全库 JSON 包含原话、元数据、历史和照片；Markdown 只导出正文。加密账号备份同样保留这些经历信息；旧备份不包含经历时，在已有经历的账号选择合并恢复。详细规则见 [经历记忆](LIBRARY.md#经历记忆)。

### 页面可以打开，但 API 报错

确认后端是否运行，并访问 `http://localhost:3000/api/health`。开发模式还应检查 Vite 的 `/api` 代理是否仍指向 `http://localhost:3000`。

### 修改 `.env` 后没有生效

必须重启 Node.js 进程。本地按 `Ctrl+C` 后重新执行 `npm run dev`；服务器执行：

```bash
pm2 restart smart-schedule --update-env
```

### 启动时报“缺少邀请码初始化配置”或“生产邀请码至少需要 12 个字符”

这表示当前进程被识别为生产环境，且数据库还没有对应角色的邀请码记录。首次部署或迁移时，应在 `.env` 中为管理员和普通用户分别配置不同且至少 12 个字符的引导值；初始化完成后，实际生效值来自数据库，重启不会重新导入旧环境变量。运行本地开发服务时，可使用 `APP_ENV=development` 和 `APP_URL=http://localhost:5173/today`。不要通过关闭生产校验来绕过报错。

### 为什么没有收到提醒邮件

依次检查：

1. 当前用户是否保存了提醒邮箱。
2. 邮件通知开关是否开启。
3. 是否处于免打扰时间。
4. `.env` 是否为统一的 163 SMTP 配置。
5. `SMTP_PASS` 是否为有效客户端授权码。
6. 通知记录中是否显示重试或最终失败原因。
7. 收件箱垃圾邮件规则是否拦截。

日报邮件还需检查：

1. 日报详情是否显示 `邮件已入队`、`邮件已发送` 或 `邮件失败`。
2. “设置”中的“日报邮件”是否已开启；它影响自动入队，日报详情中的手动发送可用于补发或重发已有日报。
3. 邮件失败后是否在日报列表显式确认重试，或在日报详情手动重新发送；系统不会对日报邮件自动重试。

本地开发还必须显式设置 `BACKGROUND_JOBS_ENABLED=true` 并重启后端；设置页的“自动提醒”只保存账号级开关，不会替代服务进程的后台任务开关。生产环境只允许唯一一个 worker 开启该配置，避免重复发送。

管理员可以在“调试日志”中按 `reminder` 分类查看扫描、筛选和队列汇总，按 `mail` 分类查看邮件通知创建、领取、发送开始、SMTP 反馈、成功落库、失败与重试。重点看同一 `notificationId` 是否依次出现 `notification_created`、`notification_claimed`、`mail_send_started`、`mail_smtp_feedback` 和 `notification_sent`；若 SMTP 没有接受收件人，会出现 `mail_send_failed`、`email_smtp_rejected` 和 `notification_failed`，并记录 `errorCode`、`lastError` 与 `nextRetryAt`。SMTP 反馈表示发件服务器处理结果，不等同于收件箱最终到达。

### 能否删除 `.env.example`

不建议。程序虽然不直接读取它，但首次部署、团队协作、灾后重建和新增配置都依赖这份模板。它也能在不泄露秘密的前提下说明环境要求。

### 能否直接编辑 `dist`

不要。它是构建产物，下一次构建会覆盖。应修改 `src/`，然后重新执行 `npm run build:client`；生产服务会直接读取最新的 `dist/`。

## 14. 安全边界

- `.env`、数据库、附件和备份均已被 `.gitignore` 排除。
- SMTP/IMAP 授权码、JWT 密钥、邀请码、OSS AccessKey 和 AI Key 都不能提交 Git。
- 用户附件不通过静态目录暴露，下载必须验证登录账号和所有权。
- 正式备份密钥应与 JWT 密钥分开，并保存在服务器外的安全位置。
- 生产环境必须使用 HTTPS。
- 删除数据库、重置服务器或执行全站恢复前，必须先生成可验证快照。

## 无固定期限待办与全天输入
<!-- product-help: user -->

行动中心的“无固定期限待办 · 查看全部”抽屉展示当前账号全部未排期 todo，包含完成历史。可按状态筛选、搜索标题/描述/备注、查看完成记录、编辑、完成/恢复和删除。历史保存时间不是执行期限；关闭无固定期限后须重新选择日期。

查看无日期待办不会生成周期或修改事项；列表只显示当前账号有权访问的数据。

新建和涉及时间字段的更新统一校验：单日全天必须使用日期或零点，todo 不保存结束时间；全天与非零时刻冲突明确拒绝。AI 导入只有日期时生成零点全天待办。历史备份仍可恢复，异常记录由桥接报告并由用户明确修正。

### 将 WorkBuddy 接入 Orbit
<!-- product-help: user -->

Orbit 已内置 WorkBuddy，无须重新开发接入。进入“设置 → AI 与模型”，在“个人 API Key”粘贴 WorkBuddy 管理页复制的原始 Key 后保存。输入框会提示中文、空白或控制字符等误粘贴内容；格式检查不代表凭据一定有效，校验失败不会覆盖已保存的 Key。

点击“测试连接（调用模型）”会使用当前账号及 WorkBuddy 默认解析模型进行一次最小生成，可能消耗模型额度；成功才提示对话连接通过。刷新模型列表只读取目录，不能替代这个测试。随后在聊天输入栏的“＋”菜单选择 WorkBuddy 及具体聊天模型；该选择与默认解析模型分别保存。配置失败时保留原内容并显示安全说明，不要把 Key 发到对话里。

在 Orbit 中询问“如何接入 WorkBuddy”时，默认按接入当前 Orbit 理解；明确指定其他程序时按其目标回答。方法咨询不会自动改设置、部署或写入正式事项；外部最新 API 细节与本项目已有功能分别说明。

### ChatGPT 个人试点
<!-- product-help: user -->
当前只开放 ORBIT_CHATGPT_OWNER_ID 指定账号；未指定时为最早创建的有效管理员。Orbit 登录和 ChatGPT 连接是两个独立身份。运行 npm run chatgpt:connect，在系统浏览器完成 loopback/PKCE 授权，在设置 → AI 导入授权文件。个人服务器导入须使用 HTTPS，服务端保留自己的 host ID，独占刷新。导入后删除传输副本；重新授权使用设置中下载的非敏感注册信息并传 --registration 参数。

同机 Nginx 必须用 `proxy_set_header X-Forwarded-Proto $scheme` 覆盖客户端协议头，并通过 loopback 连接 Node。导入接口只接受直接 TLS、本机直连或该本机代理标注的 HTTPS；外部连接的协议头、逗号分隔或多值协议头不能作为 HTTPS 证据。不同机器上的代理须按受保护的实际拓扑配置，不能直接套用本机代理规则。
访问令牌和旋转刷新令牌保存在独立加密目录，不进入普通数据导出或备份。应保护服务账号专属目录权限，单实例运行；进程崩溃留下凭据锁时，停服后核对并清理该锁。断开连接会尝试官方撤销；失败会明确显示远程撤销未确认。
灾后恢复不能依赖普通数据备份恢复 OAuth 或搜索 Key；丢失独立凭据目录/加密密钥时重新授权并重新配置搜索。保护凭据目录的专门运维备份不得交给普通用户或放入公开发布包。
模型取授权账号实际列表，不静默切换 WorkBuddy 或付费 API。仅手动聊天使用 ChatGPT；原日报与主动提醒链路保持独立。套餐资格、真实额度、OAuth 和模型工具行为仍须个人账号实测。官方流程：[注册](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)、[个人 VM](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)、[调用限制](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations)。
## 对话附件
<!-- product-help: user -->

输入栏“＋ → 图片与文件”支持 JPEG/PNG/WebP、UTF-8 TXT/Markdown/CSV、文字版 PDF、DOCX 和 XLSX。单个最多 10MB，每轮最多 3 个/20MB。上传条显示进度、解析和失败；解析完成再发送，失败可重试或移除。图片需要选择目录明确支持图片的模型，或先完成下面的手动验证；未知/不支持时会提示切换。没有文字的扫描 PDF 当前不能识别。

消息中的附件可下载；继续询问“这份文件”会使用同一对话最近的附件，多文件时请写文件名。长文按问题取节选，并保留页码；收到“只读取了节选”时可指定章节/页码追问。附件不会自动加入知识库。清理历史/删除会话同时清理相关附件；未发送文件保留 24 小时。加密备份包含附件文件和关联，普通 JSON 导出不是完整附件备份。

Office 文件只读取正文及表格值，保留段落/工作表/行定位。最多 30 个工作表、每表前 1,000 行、总计 100,000 个非空单元格；CSV 最多 200 列/前 1,000 行。所有文档最多保存一百万字符/2,000 个解析块，超限明确显示截断。公式只读取已有缓存结果，未计算时明确标记，不运行公式、宏或外部链接；加密、宏、过大压缩包和损坏文件会拒绝。

### 模型能力验证

设置 → AI → “模型能力验证”可读取实际模型列表，并分别手动验证图片输入和工具调用。点击验证会调用所选模型、消耗该 Provider 的额度；输入仅为合成色块/校验工具，不读取聊天或附件。只有实际传输与结果验证通过才显示 verified，失败保持 unknown。验证记录按账号、模型和连接版本隔离，更换 Key 后需重新验证。

### 草稿与设置定位

输入栏上方可整段点击或横向滑动切换“指令 / 记事”和“Work Buddy / ChatGPT”，也可用左右方向键选择。两组滑块共用动效；指令为主题蓝、记事为柔和玫瑰色、Work Buddy 为柔和绿色、ChatGPT 为中性色。记事隐藏 AI 服务和模型设置，保存不调用 AI。切换保留未发送文字；聊天附件与记事图片分别保留，互不替代。

记事模式的“＋ → 插入图片”支持 JPEG、PNG、WebP，也可直接粘贴图片。最多 3 张，单张 10MB、合计 20MB，计入账号附件配额。缩略图可查看大图、前后排序和移除，编辑卡片也可增删图片。纯文字仍每行一条；有图片时全部段落和图片保存为同一条，可仅图片。显式 AI 优化只处理文字，保留图片；仅图片卡片不能优化文字。

保存成功会清理输入及浏览器草稿，切换页面或会话不会恢复已保存内容。保存失败保留草稿；保存期间输入的新文字不会被旧响应清掉。未发送草稿按账号/会话保留，退出账号清理缓存。图片未绑定记事超过 24 小时后，在下一次记事图片上传时清理；过期草稿需重新上传。

图文记事的复制优先写入带内嵌图片字节的 HTML 和纯文本。浏览器拒绝时打开图文预览，可选择图文后使用系统复制，也可仅复制文字或单独复制 PNG 图片。是否保留图片由目标编辑器决定；TXT/CSV 是文字导出，完整图片请使用加密备份。废纸篓保留图片，删除聊天不会删掉记事图片。

知识库筛选收进小图标浮层，选择即生效；日报条件在筛选面板编辑，应用生效，取消不改变条件。全库导出在“设置 → 知识库”，全局搜索可定位。搜索页面使用紧凑的圆角输入框，普通页面不重复设置搜索框。候选日报和新版预览保留“非正式”标识。

“＋ → 模型设置”选择具体模型；账号记住上次服务和两种服务各自的模型，刷新或新模型发布不会来回改选。第一次没有记录且 ChatGPT 已连接时优先选择目录中的 Luna。上次模型下线时会提示重新选择；保存偏好失败可重试保存，本次选择仍可使用。Work Buddy 默认解析模型仍在设置中单独管理。

手机上的历史管理、新建对话、自动检索和主动提醒偏好在“＋ → 历史对话”中；桌面保留侧栏。消息处理期间仍可输入，后续消息加入队列。状态刷新暂时失败会显示重连提示并保留已有消息；`timeout` 表示对应请求等待超过时间限制，不能据此判断服务器没有执行。发送结果未确认时保留原输入，同内容重试会核对同一请求；日程保存结果未确认时先重新加载核对，避免重复创建。

全局搜索与日程编辑关闭后返回入口焦点。日程保存/详情操作中显示处理状态并阻止重复提交；失败保留当前表单或事项。未保存的编辑关闭前会询问是否放弃，长表单和详情在内部滚动。

“改成十点”“换到周五”“取消”优先作用于当前会话草稿；文字“确认”显示该草稿，正式写入仍需点击确认按钮。新话题会挂起草稿，可显式恢复；15 分钟后过期。部分失败只能为失败项创建新草稿，成功项不再重复。完成或延后的提醒显示服务端终态，不再保留动作按钮。

新对话创建期间会显示进度并暂时禁止输入、附件和发送，避免提交到原会话；创建完成后恢复。原会话未发送的输入仍保留，返回该会话可继续编辑。AI 正在回复时仍可输入并加入队列。

设置顶部可按名称、描述或别名搜索；方向键/Enter 定位具体项、聚焦并高亮，Escape 关闭结果。检索不包含输入值、Key 或令牌，也不会清空未保存设置。

周期表单、完成记录和本期改期保存中会暂时锁住提交与关闭，失败保留输入并把焦点移到错误。完成已登记但附件上传失败时，按钮改为“重试保存附件”，不会再登记一次完成；附件请求超时表示结果未知，先在“今日”的完成记录核对后再重试。完成备注和账单日期可以留空或清空。

知识库和日报在同一浏览会话中保留列表/阅读位置；返回时恢复筛选与卡片焦点。知识库内容 ID、哈希、关联标识和版本记录在折叠区查看。手机记事板通过关闭按钮、遮罩或 Escape 关闭；顶部滑动手柄已移除，正文获得更多高度，未保存记事草稿在重开时保留。系统启用“减少动画”后保留状态提示并取消非必要运动。

### 查看项目成长

项目成长使用一条按先后等距排列的里程碑数轴；悬停可看标题、日期和版本，点击切换架构与故事。精选演示播放五站，完整历史播放全部里程碑，没有新快照的节点会说明架构沿用。倍速可选0.5×、1×、1.5×和2×，播放中切换会保留进度，暂停继续不重置当前停留。简明/完整架构可切换，清除节点聚焦不改变里程碑。完整图可在空白处拖动、按鼠标位置滚轮缩放，用“适应画布”恢复全貌；键盘方向键平移、＋/−缩放、Home适应画布。手机默认单指滚动页面；点“操作画布”后可单指平移、双指缩放，点“完成操作”恢复浏览。详细趋势、测试与工程证据默认收起；展开说明不拉长左图。成长保持全宽舞台，个人活动报告在宽屏居中限宽，两侧空白仍可正常滚动。
