# Orbit PVE 切换与回滚 Runbook

- Status: RUNBOOK / 正式执行受人工审批闸门控制。
- Scope: 单实例、sql.js、PM2、Cloudflare Tunnel；不是生产命令脚本。
- Authority: 当前源码、[部署路径](../DEPLOYMENT-PATHS.md)、[Cloud 合同](../CHATGPT-WORK-CLOUD.md)。
- Update trigger: 版本、持久化、代理、认证、外部依赖或切换步骤变化。
- 机器地址、SSH 命令、密钥位置和确切目录只在被忽略的本机 runbook。

## 隔离环境准备

1. 留存 Phase 0 的资源和配置存在性证据；选未占用 VM ID，使用官方校验镜像、DHCP 和现有桥接。
2. 创建独立 VM；不修改 OpenWrt、PVE 管理入口、家庭路由或已有 DNS。无生产凭据的初始 VM 可先只通过现有 PVE 控制台管理。
3. 建立非 root 应用用户，独立 release/data/config/log/backup 目录。Node 采用和既有 Linux 包兼容且满足 engines 的版本；PM2 固定单 fork，禁后台和推送。
4. 按现有发布流程校验完整包。在空白 DATA_DIR 启动并做合成测试；不要用正式数据充当隔离测试。
5. 配置仅回环 Nginx，防火墙拒绝 Node 直入。Tunnel 仅映射测试 hostname 到该 Nginx，末尾 catch-all 返回 404；凭据文件不进入 release。
6. 转发头必须可解释：若 Nginx 从仅可由 cloudflared 到达的入口接受 CF-Connecting-IP，并**覆盖** X-Forwarded-For/Proto，Express 可只信任 Nginx 一跳。若保留完整代理链，则按实际链路重新测试，不能盲设一跳或两跳。
7. 完成 [测试域验收](MIGRATION-CHECKLIST.md#3测试域名与-https)。新增安全访问/凭据和公网暴露在实际执行时按授权处理；不要把整个站点加上会拦截 MCP 的交互式 Access。

## 正式切换前的停止条件

以下任一项未满足，保持旧生产运行：新环境无法重启恢复、Tunnel 外部路径不稳定、容量不足、无一致性备份或恢复证据、关键密钥不齐、存在未知写进程、无法处理新版数据回滚，或仍未取得 Phase 5 明确批准。

准备一份受控资产 manifest：四库、附件/媒体、vault、CalDAV ledger/control/锁、配置、Firebase、代理/规则文件、timer、PM2 环境、旧代码/runtime。分别记录大小、数量、权限、hash；不在公开报告放文件内容和敏感路径。

## 正式停写与切换（需要明确批准）

1. 回读批准范围、维护窗口、冻结 commit、DNS 原值和备份位置。确认新 VM 的所有正式后台开关仍关闭。
2. 停止外部写入口、正式 worker 和所有可能写同一套数据的进程；不因暂停服务擅自更改 Work 排程。等待受控关闭，核对进程/端口/文件稳定性。正在执行的 Work/外部发布应先排空或明确拒绝写入。
3. 在旧机停写状态下备份完整运行资产；检查 journal/marker，不能删除未知恢复事务。记录四库及文件 hash 后再次核对未变化。加密备份传到独立故障域，验证可解密/可恢复。
4. 获批准后在旧机与新机之间传输生产数据/密钥，核 hash、数量、权限和属主；不把生产数据下载到开发仓库。不用账号导出替代机器级迁移。
5. 使用**目标版本**在恢复副本中检查数据库完整性、外键、启动迁移和账号/文件关联。若存在 schema 差异，先证明新写入后旧代码是否仍兼容；没有证据时不得承诺原地代码回滚。
6. 新实例保持 worker 关闭并从内部验收，确认 APP_URL 的 origin、OAuth issuer/resource、外链、Cookie、代理及外部网络正确。启动恢复副本会写文件，必须使用已批准的副本和受控目录。
7. 根域切换获批准后，精确替换已记录的冲突 Web 记录，保留邮件及其他业务记录。验证权威 DNS、TLS 和实际新环境版本。TTL/缓存过渡期间旧入口仅维护或反代到唯一新数据源，不继续写旧库。
8. 确认只有新机一个正式 worker 后启用后台任务；FCM、CalDAV、正式 Work 和邮件仍按各自批准逐项恢复。按检查表留证，记录最后旧机写入和首次新机写入的边界。

## 回滚

| 时点 | 处理 |
| --- | --- |
| 新机尚未接收正式写入 | 保持新 worker 关闭；恢复原 DNS/旧入口；确认旧版本与数据未变后按批准恢复旧 worker；保留新现场 |
| 新机已经接收正式写入 | 先冻结新写入/worker，对最新新机资产做一致性备份；核对与旧代码的数据兼容性；安全回传**最新**数据，或在 ECS 运行同目标版本后恢复；最后才回切入口和唯一 worker |
| 数据兼容性或完整性不明 | 继续维护状态并保留两端现场；不得用切换前冷备覆盖新增数据；评估单独批准的恢复/重放方案 |

回滚 DNS 不能代替数据回滚；恢复旧代码不能恢复已撤销的登录和 OAuth 授权。回滚要核版本、静态 hash、登录/核心数据、代理和唯一 worker，而不仅是 health。

## 稳定与备份

保持 ECS 和旧材料至少到 48～72 小时观察与回滚演练结束。检查 BIOS 来电恢复、笔记本合盖、PVE/VM/PM2/Tunnel 自启，不能为验证擅自重启承载 OpenWrt 的宿主机。宿主重启/断网演练单独约定窗口。

复用 [受控运维与保留](../DEPLOYMENT-PATHS.md#受控运维记录与保留)，先 dry-run，再按批准安装 timer/执行清理。备份必须是应用协调或停写的一致性快照，定期在独立空目录恢复；异机副本应离开 PVE 及其硬盘故障域。NAS 若同家庭电源/网络，仍记录地域灾难风险。PVE snapshot 仅辅助恢复。

观察项含资源、磁盘增长、SSE 中断、Tunnel 重连、后台积压、备份新鲜度与失败通知。未验证的外部业务继续保持未验证，不据运行 72 小时自动判为通过。
