# Orbit PVE 性能与 OpenAI 代理专项报告

- Status: SNAPSHOT / 2026-10-24 第二轮，隔离 staging 已实施；正式迁移未批准。
- Scope: 性能分层、公开静态资源缓存、OpenAI 专用出站与新 VM 重启；无生产数据或正式 AI 凭据。
- Baseline: 性能前后对照均为 `0.63.0-261023.0004` / `239eea1`；随后部署代理补丁 `0.63.1-261024.1759` / `f8e6d5f`。
- Authority: 现场逐次采样、浏览器时间线、当前源码与 Linux 制品 manifest；精确机器地址、命令、原始 JSON 和截图只保存在被忽略的本机记录。
- Update trigger: 新性能或业务证据另加日期快照，不改写本次测量；通用操作方法只在 [迁移 Runbook](MIGRATION-RUNBOOK.md)维护。

## 结论

本轮所测请求的主要等待发生在公网路径。回环业务响应中位数约 2.4 ms、LAN 约 4.0 ms，公网约 600 ms；独立云端客户端也观察到约 850 ms 的测试站响应。公开静态 JS/CSS 原先缺少长期缓存，补上内容寻址缓存后，公网中位数分别从 588/601 ms 降为 254/259 ms。动态接口没有同步改善，不能宣称全部卡顿已解决，也尚不能把公网开销继续分解到具体运营商、Cloudflare 边缘或 Tunnel 单一环节。

当前 2 vCPU / 3 GiB / 40 GiB 的测试 VM 资源够用，不建议扩容。OpenAI 直连失败位于 TCP 建连阶段；复用已有带认证的 OpenClash 代理后，部署代码的 API、OAuth 元数据和 JWKS HTTPS 检查通过，并在新 VM 重启后保持有效。未调用真实模型或完成真实 OAuth 授权。

没有修改 OpenWrt、AdGuard、家庭路由、DNS 或分流配置，没有重启其服务。复用端口原本已对 LAN 监听且要求认证；本轮没有实现 VM 专属来源 ACL 或独立代理身份，这项最小权限加固仍待维护窗口处理。没有扩大其现有监听范围或取消认证。

## 分层性能

每个目标每条路径 20 次顺序 curl、间隔 500 ms、独立连接、压缩开启；业务目标是已登录账号的无日期日程只读 API。失败不纳入成功耗时分位数，但单独计数。P95 为排序后 nearest-rank；表内单位均为 ms，格式为中位数 / P95。

受限 LAN 入口只允许工作机，带自动到期；没有开放 Node 端口。工作机本身存在既有 Mihomo TUN，`--noproxy '*'` 只能排除显式 HTTP 环境代理，不能排除 TUN，因此公网数据表示工作机常态网络。独立 ECS 客户端仅作网络交叉验证。

| 目标 | VM 回环 | 工作机 → LAN | 工作机 → 公网 |
| --- | ---: | ---: | ---: |
| health | 1.4 / 1.6 | 3.3 / 20.2 | 882.7 / 1970.9 |
| HTML | 2.2 / 2.8 | 4.0 / 6.5 | 608.7 / 978.8 |
| 入口 JS | 2.0 / 2.6 | 4.9 / 21.9 | 588.2 / 1491.7 |
| 主 CSS | 2.5 / 27.1 | 5.6 / 28.5 | 600.6 / 1129.0 |
| 已认证只读业务 API | 2.4 / 3.7 | 4.0 / 6.1 | 599.6 / 983.9 |

回环、LAN 各 100/100 成功；公网 99/100 成功，health 一次客户端 TLS 握手失败，curl 35、约 5 秒。不是 HTTP 业务错误，不把失败算成成功分位数。

### 缓存优化的同版本前后对照

只为确认具有八位内容 hash 的 `/assets/` JS/CSS 添加 `public, max-age=31536000, immutable` 与 gzip；不缓存 API、认证、附件、媒体或受保护 Tools。没有新增 Cloudflare 全局缓存规则，也没有清空共享缓存。

| 公网静态资源 | 优化前 | 最终配置后 | 后测失败 |
| --- | ---: | ---: | ---: |
| 入口 JS | 588.2 / 1491.7 | 254.0 / 803.7 | 0/20 |
| 主 CSS | 600.6 / 1129.0 | 259.0 / 329.7 | 0/20 |

两个中位数均约下降 57%。这证明缓存机制与该窗口的改善，不保证任意网络同幅度提速。gzip 先用默认级别测一轮，再调为 6 并重测静态资源；LAN gzip 6 后 JS/CSS 传输体约 33/39 KB。Cloudflare 的旧 URL 曾继续提供正确的旧压缩表示，不能把该体积等同最新源站 gzip 级别。部署新补丁后另核对 HTML 引用的六份 JS/CSS：内容 SHA 与冻结制品一致、类型正确、缓存头符合预期、重复请求均 HIT；未授权业务 API 为 401/DYNAMIC。

同版本完整后测 100 次无失败，但 health 中位 919.4 ms、HTML 641.3 ms、业务 API 858.9 ms，均未改善。公网动态路径仍是后续最有价值的调查方向；没有为此扩大 VM 资源。

### 浏览器交互证据与限制

使用独立 Chrome 标签采集实际 `/today`、日历导航、Network 与 Tracing，未操作用户原有标签。auth/me 完成后 profile/action-center 并行发出，多个请求约 400 ms；初次日历懒加载有约 849 ms 的模块请求和约 1949 ms 的重验证请求。观察到自有 renderer 主线程约 860–975 ms 的长任务，也有扩展脚本活动。

进一步 CPU 采样约 2.7 秒中，大部分样本为 idle/program，`scrollIntoView` 自耗时约 37 ms、GC 约 15 ms，未定位到可归责的大型业务 JS 热点。不能仅凭压缩后的 React scheduler 栈就重写日历，也不能把扩展和自动化 DOM 观察开销算作应用执行。本轮未改变前端源码或裁剪功能。

工具观察的 warm today 约 1.27 秒、初次日历约 2.17 秒、重复日历约 0.88 秒，包含控制与等待开销，**不是 INP**。EventTiming/正式 INP 未采集，原始时间线与可在 DevTools 打开的 CPU profile 已保存在私有证据目录。后续应在无扩展的受控浏览器录制同一手动交互，结合完整网络瀑布与主线程拆分再决定局部优化。

## OpenAI 直连与代理

### 已确认的故障阶段

VM 原默认网关和 DNS 指向家庭主路由，没有将 VM 改为透明代理客户端。OpenAI API 直连在 TCP 建连阶段约 6 秒超时，尚未进入 TLS；OAuth 主机直连可完成有效 TLS 但收到 403。这与“全部 OpenAI 端点不可解析”不同。

VM 当时未收到 Fake-IP 地址；其 API DNS 答案与通过已认证代理的独立 DoH 答案不一致，说明解析/直连路径有异常或差异，但未确定具体上游原因。不能据此认定 OpenAI 故障或关闭 TLS/SSRF 检查。无认证访问已有 Mixed 代理迅速返回 407，证明端口可达且认证生效；携带已有认证后，HTTP CONNECT 和 SOCKS HTTPS 探针取得 API 401、OAuth metadata 200，证书校验保持开启。

### 接入方式

新增私有配置 `ORBIT_OPENAI_PROXY_URL`，只对精确的 `https://api.openai.com` 和 `https://auth.openai.com` 使用每请求 Undici `ProxyAgent`。其他请求保留原 fetch/agent；没有设进程级 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NODE_USE_ENV_PROXY`，没有设置全局 dispatcher，也没有修改系统路由/DNS。

代理 URL 和认证只保存在新 VM 的私有配置与受限 PM2 保存环境中。URL 校验拒绝多余路径/查询/片段和控制字符，错误不回显认证；CONNECT 的代理认证与目标 Authorization 分离；保留原 signal/超时并拒绝重定向，避免跨 origin 代理。代理失败显式报错，不隐式回退直连。WorkBuddy 独立子进程环境保持原合同。

`undici` 7.29.0 已存在于解析锁树，本次将其声明为直接依赖；除根声明和版本外，完整 resolved lock 内容与既有 Linux runtime 相同，实际安装版本也已核对。没有引入新解析版本，没有复制 Windows 依赖。目标 Linux 重新跑类型/服务测试、原生和帮助准备闸门，1242 份源码 hash 无差异。

### 部署与重启结果

切换前只停止 staging，冷备完整当前测试 DATA_DIR、私有环境、PM2 dump 和启动配置，保留旧 release，并核对冷备归档 SHA。随后切换 current、从私有环境启动唯一非 root fork，保存 PM2；后台、主动、FCM、CalDAV 仍全部关闭。没有读取或复制旧生产密钥。

只读控制器显示 OpenAI selector 选择既有代理组；仅筛选本 VM 的日志，确认 API/auth 请求命中 `DomainSuffix(openai.com)`，经 OpenAI 规则走既有香港节点。没有更改节点选择。dnsmasq 仍转给本机 AdGuard，后者保留一个上游；本机 DNS 查询可应答，Fake-IP 模式保留。代理核心启动时间早于本轮，dnsmasq/AdGuard 均继续运行；没有执行 OpenWrt 重启。

认证存在于运行配置和 OpenClash 持久 UCI authentication 节中，原始订阅 YAML 不含该认证；OpenClash 服务已 enabled。配置存在性与自启标志不能代替实际重启或订阅更新后的恢复验证。已有 LAN 认证共享端口不等于 VM 专属最小 ACL，不能把现状写成已完成独立凭据/独占来源限制。代理配置被订阅更新覆盖、节点不可用和路由器重启恢复仍是正式迁移前的复核点。
