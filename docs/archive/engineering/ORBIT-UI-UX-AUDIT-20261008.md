## 五项优先问题

### 1. [P1] 时间选择“取消”没有撤销修改

- 位置：`src/components/calendar/ScheduleFormModal.tsx:45–58,139–145,538–548`。
- 实测：新增日程原值 09:00–10:00，打开开始时间并选 11，点时间弹层“取消”后仍显示 **11:00–12:00**。未提交正式日程，但下一次保存可能带入以为已放弃的时间。
- 根因：点小时/分钟立即调用父级 onChange；取消只恢复到已经更新的 current 值。开始时间预览还会自动推后结束时间。
- 修正：弹层内保持草稿，仅“确定”提交；取消/Escape 放弃草稿并回到原值。优先这种方案，避免预览加双字段撤销逻辑。
- 证据：A-E02 的前后可访问树数值与直接源码因果。Chrome 后续控制超时不参与此缺陷判断。
- 建议命令：`/impeccable harden`。

### 2. [P1] 时间选项无法通过键盘选择

- 位置：`src/components/calendar/ScheduleFormModal.tsx:95–110,118–133`，开始/结束/待办时间共用。
- 实测：桌面明色与 390 暗色中，Tab 进入滚动 DIV，时分选项只有 onClick，无 role、tabIndex 或键盘更新行为。能开关弹层不能证明能改为所需时间。
- 影响：依赖键盘的用户无法完成核心的精确时间编辑。
- 修正：优先复用既有可访问时间控件；保留自定义时分列表时需有选择语义、选中值、方向键/Enter/Escape 与一个活动焦点。无需新框架。
- 证据：A-E03 DOM 与 Tab 操作、源码；未运行真实读屏软件。[W3C Keyboard](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html)
- 建议命令：`/impeccable harden`。

### 3. [P1] 暗色“编辑个人资料”链接对比不足

- 位置：`src/components/settings/sections/AccountSettings.tsx:12` 与 `src/components/library/LibraryPreferencesPage.tsx:98`。
- 实测：链接前景均为 `rgb(0,0,238)`；账号设置背景 `rgb(36,36,36)` 时约 **1.65:1**，日报设置背景 `rgb(18,18,18)` 时 **1.99:1**。均为普通小文本，低于 4.5:1 基线。[W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- 影响：用户难以读清连接个人资料与偏好的重要入口。
- 修正：给这类链接复用主题颜色与非颜色识别，检查明暗、visited、hover 和 focus。两处已证实，不扩大为“全站所有链接失败”。
- 证据：A-E05；B 的 dark-link-computed.json 和暗色截图；两代理分别复核不同入口。
- 建议命令：`/impeccable harden`，可用 `/impeccable colorize` 处理主题 token。

### 4. [P1] 主日历前后箭头缺少可访问名称

- 位置：`src/components/CalendarView.tsx:1467,1476`。
- 实测：四尺寸 DOM 均有两枚仅含 Chevron SVG 的 button，无 aria-label、title 或可见文字；迷你月历已有名称。
- 影响：按钮虽能聚焦，辅助技术无法说明切换哪个时间范围。[W3C Name, Role, Value](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html)
- 修正：依当前视图标记“上一天/下一天”“上一周/下一周”“上个月/下个月”等，保留焦点轮廓。
- 证据：B 的 schedule DOM 与源码。没有真实读屏实测。
- 建议命令：`/impeccable harden`。

### 5. [P2] 统计热图有 168 个无动作焦点

- 位置：`src/components/UsageStatisticsView.tsx:38`、`src/styles/orbit-statistics.css:1`。
- 实测：7×24 个格子都是默认进入 Tab 顺序的 button，没有点击任务；A 实际从第一格 Tab 到第二格。390 时每格约 **9.2×9.2px**。未实按 168 次 Tab，数量由 DOM/原生语义确认。
- 影响：键盘用户要经过大量没有结果的控件才能继续阅读明细；手机也无法稳定逐格探索。
- 修正：只读图表使用分组说明与可展开的数据表；确有钻取需求时采用一个 Tab 入口、方向键移动和明确结果。保留数据可访问性，勿仅删除名称或机械放大全部格子。
- 证据：A-E04、B 的 stable-measurements.json 与源码，双方独立发现。
- 建议命令：`/impeccable harden`；有钻取需求时结合 `/impeccable adapt`。
