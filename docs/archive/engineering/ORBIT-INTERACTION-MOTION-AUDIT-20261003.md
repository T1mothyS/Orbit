## 0. 设计结论与需求口径

Orbit 的高级感应来自清晰的层级、稳定的布局、准确的反馈和可预测的操作。当前优先级是释放聊天阅读面积、统一任务状态与面板行为，其次才是跟手和连续过渡。无需整体换框架，也无需把每个组件都做成动画。

本方案以用户本轮提供的详细《Orbit UI/UX 高级交互与 Motion 专项审计》为主要审计要求，结合当前源码和隔离浏览器结果。附件中的建议作为设计输入，不作为部署、真实模型调用、发信或修改正式数据的授权。本轮仅计划。

沿用此前用户认可的聊天布局方向，并明确：

- 输入栏左侧“＋”，右侧“发送”；记事模式右侧为“保存”。
- 两组带文字的双选滑动控件：“指令 / 记事”“Work Buddy / ChatGPT”，同时支持点击与键盘，滑动限于控件自身。
- 具体模型、附件、历史会话和新建会话收进“＋”面板；手机取消独占一行的“对话列表”，历史功能仍保留。
- 恢复上次的服务和具体模型；每个服务分别记忆。首次无记录且 ChatGPT 可用时才优先目录中的可用 Luna，不硬编码版本，不随模型目录排序或升级换模型。
- 不可用、断连、读取失败时解释原因并让用户选择，不静默换服务或模型。沿现有账号偏好接口扩展持久化，让再次登录和不同设备保持一致；保存失败明确反馈。
- 记事模式不调用 AI；切换时保留文本与已选附件，附件不随记事保存发送，也不静默丢弃。

### 1.3 Visual Design：当前问题与目标规则

| 维度 | 当前具体问题 | 推荐规则 |
| --- | --- | --- |
| 信息层级 | Orbit、个人事务中心、AI 对话、对话列表多次表达当前位置；模型配置与发送争夺面积 | 每个工作区只保留一个清晰标题；高频操作常驻，低频设置渐进展开 |
| 操作优先级 | 知识库手机首屏把“刷新”“导出全库”做成两个宽按钮，导出使用强主色，阅读内容排在后面 | 搜索、筛选和内容为主要任务；导出进入次级菜单，刷新为轻量按钮 |
| 字体 | 系统字体已足够；各页使用 12px 控件、14/15px 消息、较大页面标题与英文眉题，层级节奏不同；手机输入实测 14px | 不加字体依赖。应用正文 14–15px，手机输入 16px；阅读正文 16–18px；元信息一般 12px，避免继续缩小。手机输入缩放风险留真机验证 |
| 字重 | 粗标题、卡片标题、徽标和强调文字同时出现 | 一屏最多突出页面主题与当前操作；正文依靠内容组织，不整段加粗 |
| 颜色 | PNG 彩色导航与 Lucide 混用，活跃背景、分类色、状态色共同抢视线 | 中性底色、一个品牌强调色；分类色只作细标记；成功/警告/错误按语义使用，并配文字 |
| 间距 | 聊天拥挤，知识卡片短内容却占较大高度；标题说明、按钮和筛选占多行 | 沿 4 / 8 / 12 / 16 / 24 / 32px 节奏；按内容决定卡片高度。手机减少外壳层，桌面保留工作密度 |
| 圆角 | 既有 token 为 6 / 8 / 12px，实际还有 15 / 17 / 18 / 19px 与大量 rounded-* | 普通控件 6–8px、内容卡 8–12px、面板 12–16px；胶囊只用于真正的状态/模式，不把所有内容圆成气泡 |
| 边框/阴影 | 卡片套卡片、控件边框、容器描边和悬停阴影叠加 | 普通内容用留白和一层浅边界；阴影只说明浮层高度，不用卡片悬浮来表示“高级” |
| 导航 | 常见桌面宽度和手机六个入口没有可见短名称；宽屏到 1600px 才显示名称 | 桌面保留可见短名称，当前入口加 aria-current；手机评估“对话、今日、日程、更多”，更多保留提醒、日报、知识库，均可直接到达 |
| 阅读层级 | 知识正文与内容 ID / 哈希 / sourceId / 发布链路同时呈现；英文工程眉题频繁出现 | 阅读优先；来源/更新时间可见，技术元数据收进“内容信息”。不删除来源证据，不把待确认关系伪装成已确认 |

推荐三类布局共用视觉规则：

1. **聊天工作区**：桌面可见会话侧栏、消息区、按需记事板；手机紧凑标题、消息区、底部两层输入，历史和低频工具进面板。
2. **事项工作区**：今日、日程、提醒共用事项摘要、日期、优先级和动作语言；桌面支持密集浏览，手机一次突出一个下一步动作。
3. **阅读页面**：日报与知识正文保持专注阅读，统一返回、来源、目录、更多入口；日报继续保留新闻编辑层级与已认可的图片/标题关系，不强套聊天气泡。

手机导航的四入口方案是待原型验证的建议，不在本轮改变任何入口或深链接。微信参考主要用于输入栏与渐进展开，不照搬其整套导航到桌面。

产品性格对应到具体规则：**安静**是稳定正文和低幅状态提示；**快速**是点击立即反馈、工作继续进行；**克制**是有限颜色与短过渡；**智能**是准确区分排队、工具、确认和结果；**有生命感**只表现为实际处理时的微弱状态变化。避免夸张 bounce、大量发光、无意义渐变、随机飞入和把所有组件都动画化，不营造模型拥有情绪的假象。

## 3. Top Issues

### P0：先修真实反馈与操作可靠性

1. **日历失败可能表现为“成功”。** CalendarView.handleDelete 不检查 response.ok，HTTP 500/403 等仍会过滤本地事项。handleAddSchedule / handleEditSchedule 收到带错误的 JSON 后，即使没有 data.schedule，也会关闭表单。handleToggle 的异常静默；ScheduleFormModal 没有保存中保护，onSave 合同也不能返回局部错误。这是源码可直接确认的失败路径；本轮未对正式接口制造失败，也不把它夸大为已证实数据库数据丢失。第二阶段先做合成失败回放，再修。证据：[CalendarView](../../../src/components/CalendarView.tsx)、[表单](../../../src/components/calendar/ScheduleFormModal.tsx)。
2. **所有改造保留确认、幂等和草稿归属。** 这是实施硬门槛，并非声称现有聊天防重复保护缺失。手势松手不能等同于确认写日程；动画结束不能决定业务成功；错误后不能自动生成新 requestId 重发。已有 expectedRevision、请求归属、创建保护、研究确认边界必须保留。

### P1：直接影响日常使用

- 手机外壳与输入区占比过大；实现已认可的紧凑输入与＋面板，移除独立对话列表行。
- 模型偏好没有按用户要求保存恢复；目录第一项不能作为每次切换的默认。
- 全局搜索的焦点逃逸已在浏览器确认；记事抽屉、日历导航和手写表单需补齐相同规则。
- 日历读取失败只记日志，不能让“未读取成功”看起来像“没有事项”；部分邮箱读取也需同类核对。
- 请求、工具、确认与结果的空间关系不清楚；恢复时旧错误仍可能保留，不能靠红色整行常驻来表示当前状态。
- 控件状态、字号、圆角和动作优先级不一致；优先修重复层级、嵌套卡片与高频控件。
- 条件卸载 / display:none 让退出突然截断；CSS reduced-motion 不能覆盖显式 JS smooth 定位。
- 知识库导出、技术元数据和日报来源切换抢占阅读；优先恢复内容与返回上下文。

### P2：在基础行为稳定后验证

- 可中断、可取消的面板拖动与轻微边界阻力。
- 短列表在真实成功后局部位置连续；只在确有追踪需求时试验。
- 日历拖移的落点/时间/冲突预览；当前没有这条交互，不把它称为“修现有拖拽 Bug”。
- 更多页面共用结果卡、适当提取重复小组件；不按文件行数发起重构。
- 低性能设备与长列表性能测量；现阶段只确认 repaint 风险，没有证明全站掉帧。

## 4. High-impact Opportunities

下面九项覆盖最值得改善的位置。“低 / 中 / 高”是相对实现复杂度；所有持续时间都是拟定参数，尚非真机调优结果。Rive 在这九项中均无必要。

### 4.1 输入栏、模式切换与模型记忆

- **当前 / 问题**：下拉、附件行、记事开关和输入框分散；选择服务会读目录第一项；手机需要为设置保留整块高度。
- **建议 / 收益**：两层输入栏、两个双选控件与＋面板；文字始终清楚表达选中项。触点跟随只预览选择，松手才提交偏好；反向拖回或 pointercancel 返回原选择。释放面积并避免误选。
- **起止 / 参数**：点击或横向手势触发，选中底板从旧位置移至目标；跟手不加滞后，释放 120–160ms move easing。进入记事只替换按钮/说明 80–120ms，不移动整个对话列表。
- **实现**：基础 CSS；少量 Pointer Events 负责预览与提交，CSS 本身不负责手势状态。两项有限位置无需 Motion / use-gesture / Rive。
- **复杂度 / 风险 / 平台**：中；偏好持久化、晚到目录覆盖、跨账号和草稿归属是主要风险。桌面点击/方向键，手机点击/控件内横滑；手势不能成为唯一入口。

### 4.2 手机＋面板与记事抽屉

- **当前 / 问题**：记事板 display 开关，退出没有连续路径；＋面板是新设计目标。
- **建议 / 收益**：统一面板标题、关闭、遮罩、Focus trap 和返回焦点；可拖区域用明确把手。拖动期间预览后方消息，未过阈值释放回原位，跨阈值才关闭。用户能看清面板与内容的空间关系。
- **起止 / 参数**：＋点击：面板由底部外侧→可见，220–240ms enter；关闭反向 160–180ms exit。拖动从当前视觉位置开始，跟手直接更新 transform；释放使用无明显 overshoot 的 spring，预期约 200–300ms 收敛，实际以原型测量为准。
- **实现**：普通开关先 CSS + 显式 opening/open/closing 生命周期。只有跟手、速度连续、快速反转确实让小实现变复杂时，再评估 Motion 的 motion value / drag；不用同时加入 react-spring。
- **复杂度 / 风险 / 平台**：中到高；内容滚动、软键盘、选择文字、嵌套弹窗和 pointercancel 是主要风险。桌面只做短面板过渡，不要求拖动；手机把手拖动，主体保持原生滚动。

### 4.3 请求、Thinking、工具与回复的交接

- **当前 / 问题**：任务状态独立滚动；完成后状态条消失、回复出现，位置关系弱。
- **建议 / 收益**：每次请求拥有稳定的状态位置：排队→正在处理→真实工具步骤→结果或失败。默认摘要一行，详情可展开；长耗时可取消，重复点击有单项提交反馈。当前链路按完整回复交接，避免假装前端已流式渲染。
- **起止 / 参数**：真实事件触发，状态图标/短标签局部 120ms opacity 交替；完整回复新增 120ms opacity 0→1；处理圆点 1.8s ease-in-out，仅 opacity .45→1。完成停止循环，不让旧历史再次进场。
- **实现**：CSS 足够；不让所有消息拥有 layout 动画。将来真正的 token 流逐帧直出，只对真实终态做交接。
- **复杂度 / 风险 / 平台**：中；请求关联、SSE 重连、重复最终回复、读旧消息时抢滚动。桌面与手机都适合；默认步骤不扩大整屏。

### 4.4 待确认计划→提交→执行结果

- **当前 / 问题**：状态和确认保护已具备，卡片内变化缺少统一组织；日历另一路失败却可能关闭表单。
- **建议 / 收益**：保留卡片摘要和项目位置，只改变动作区与结果区。区分“正在提交确认”“已接受/正在执行”“全部成功”“部分成功”“失败”。服务器失败保留可编辑内容，不能只关闭或弹 Toast。
- **起止 / 参数**：点击立即给按压/忙碌反馈 80ms；真实状态到达时局部淡入 120ms；终态结果 120–160ms。需移入已完成分组时，结果先可读，再执行用户允许的布局变化，不用固定延时模拟成功。
- **实现**：CSS 优先；卡片本体不缩放、不翻转。确需少数列表位置连续才试 Motion FLIP，业务状态完全不依赖其回调。
- **复杂度 / 风险 / 平台**：中；失败重试、重复确认、过期/版本变更、部分执行。桌面/手机均优先。手势关闭只是关闭查看层，不能隐式确认或撤销已执行任务。

### 4.5 今日完成与主动提醒处理

- **当前 / 问题**：主动提醒 handled 后已移除动作；今日完成会改变所在分组，容易让用户找不到刚处理项。
- **建议 / 收益**：原位置立即显示真实结果，“已完成 / 已延后到…”替代动作；已完成区有清楚入口。只在对应接口支持时提供恢复/撤回，不暗示所有操作可撤销。
- **起止 / 参数**：接口成功触发，动作区 opacity 1→0，结果 0→1，120ms feedback；提醒首次进入可 y4→0、opacity 0→1，160ms enter。重载、轮询和历史提醒不重放。分组移动最多 180–220ms move，且只针对处理项附近。
- **实现**：主要 CSS；可选的小范围位置动画另评估，默认不安装 AutoAnimate。
- **复杂度 / 风险 / 平台**：中；焦点随按钮移除、后台并发处理、提醒重复和已失效。两端适合，长列表尤其应保持滚动锚点。

### 4.6 搜索、Dialog、Dropdown 的同一套层级行为

- **当前 / 问题**：设置焦点规则较完整；搜索、部分抽屉与手写表单不一致，关闭可能直接卸载。
- **建议 / 收益**：统一关闭优先级：当前子弹层→父弹层→页面；进入聚焦、背景隔离、退出回原触发按钮。保存期间的限制由业务决定并有解释，而非由动画决定。
- **起止 / 参数**：打开：遮罩 opacity 0→目标 120–160ms，内容 opacity 0→1 / y4→0 160ms enter；关闭沿原方向 120ms exit。菜单保持锚点，最多 y2–4px；重复开关从当前状态反转，不排队。
- **实现**：先沿 TDesign 生命周期；手写层用 CSS + 存在状态。AnimatePresence 只在确需统一 React 退出管理且能降低复杂度时评估，不为单个 fade 安装库。
- **复杂度 / 风险 / 平台**：中；嵌套 Select、Portal、焦点恢复目标被删、减动时生命周期清理。两端优先，桌面键盘价值尤其高。

### 4.7 日历导航、日期定位与落点预览

- **当前 / 问题**：日历侧栏无跟手；Agenda 已在 wheel/touch/pointer/keyboard 输入时取消程序化滚动守卫，但显式 smooth 和估算窗口仍待统一。
- **建议 / 收益**：先完善日期定位和面板，不替换原生滚动。将来若验证拖动需求，先显示目标日期/时间/冲突预览；取消回原位置，放手也不能绕过既有确认与权限。
- **起止 / 参数**：侧栏开关 x方向 220/180ms；日期选中只底板/文字 80–120ms。程序化定位可被用户即时接管，减动立即定位。未来拖动目标跟手无过渡，取消回位短 spring；网络保存失败回到真实状态并解释。
- **实现**：现阶段 CSS 与滚动状态修正即可。正式拖日程高复杂度，需独立评估 Motion 或手势库，不在首轮加入。
- **复杂度 / 风险 / 平台**：定位中、数据拖动高；滚动与选择冲突、全天/跨日/周期/时区语义。两端定位适合；手机全屏横滑翻月暂不采用。

### 4.8 附件上传→解析→可发送

- **当前 / 问题**：上传进度真实，处理状态也存在；不同阶段需要更明确，附件行不必空时常驻。
- **建议 / 收益**：稳定附件行，图标与短说明局部切换。上传 100% 后明确“正在解析”，可取消/重试；失败贴近附件。选择模式不会自动丢文件。
- **起止 / 参数**：选择后新增行 opacity 0→1 120ms；上传百分比直接反映事件，最多 80–120ms 线性更新条；解析不显示虚构百分比；ready / failed 只图标和文字淡入 120ms。
- **实现**：CSS；进度条用 transform:scaleX，附件处理沿已有异步保护。无需 Motion / Rive。
- **复杂度 / 风险 / 平台**：低到中；删除与解析并发、换会话、长文件名。桌面和手机均适合；多文件列表不每行飞入。

### 4.9 阅读、筛选与返回上下文

- **当前 / 问题**：知识列表和详情技术信息较重；日报来源、统计条件切换会清空内容，容易闪白和丢位置。
- **建议 / 收益**：筛选区稳定，刷新只在受影响区域表示；新来源旧正文不能冒充当前结果。旧内容可短暂保留但明确“正在切换”、暂停其写操作，或使用尺寸稳定的占位；返回恢复筛选与位置。阅读身份稳定比大型页面转场更有价值。
- **起止 / 参数**：用户明确切换后，新区块 opacity 0→1 100–140ms；目录活跃标记 80–120ms；返回直接恢复位置。默认页面切换无动画，可选轻微淡入，不做整页横向飞行。
- **实现**：CSS + 路由/数据状态保持；稳定 key 与请求版本控制。共享布局只作为小标记或选中底板的后续候选，不把整个文章卡扩成全文动画。
- **复杂度 / 风险 / 平台**：中；来源错配、晚到请求、阅读位置/图片尺寸。两端适合，手机收益显著。

## 5. Motion System Proposal

### 5.1 统一 Token

沿已有命名扩展规则，不新增一套竞争系统。默认选择现有短时长，只有空间距离或交互需要时增加差异。

| 类别 | 进入 / 更新 | 退出 / 释放 | 属性与幅度 | 曲线 |
| --- | --- | --- | --- | --- |
| micro interaction | 80ms | 80ms | 背景/边框/图标颜色；普通按钮不缩放整块内容 | enter |
| local feedback | 120ms | 80–120ms | 图标/短文字 opacity；不淡出整个工作区 | enter / exit |
| component entrance/exit | 120–160ms | 100–120ms | opacity 0↔1；确有来源关系才 2–4px 位移 | enter / exit |
| overlay | 遮罩 120–160ms，内容 160ms | 120ms | 遮罩 opacity；内容 y4→0；不放大背景页 | enter / exit |
| panel transition | 桌面 180–220ms，手机 220–240ms | 160–180ms | 侧栏沿 x、底部面板沿 y；方向与入口一致 | enter / exit |
| page transition | 默认 0；必要时 100–140ms | 0–100ms | 只新内容淡入，布局框架稳定 | enter |
| shared layout | 可选 180–220ms | 同一位移路径 | 小选中标记或少量列表邻项的 transform；禁全文缩放 | move |
| loading / thinking | 状态立即出现 | 真实结束即停止 | 1.8s 低幅 opacity 循环；没有真实进度不显示百分比 | ease-in-out |
| AI state | 120ms | 80–120ms | 请求、工具、结果仅受影响子区交接 | enter / exit |
| notification / reminder | 新到达 160ms | 处理结果 120ms | y4→0 可选；历史恢复无入场 | enter |
| success / error | 120–160ms | 用户关闭或真实恢复时 120ms | 文本、图标、语义色；无 shake、bounce 或闪光 | enter / exit |
| gesture follow / release | 跟手直接更新，0 额外滞后 | CSS 120–240ms 或 spring | 从当前位移出发，速度参与释放，不从初始帧重放 | move / spring |

- enter：cubic-bezier(.2,0,0,1)，沿已有规则。
- exit：cubic-bezier(.4,0,1,1)，沿已有规则，退出通常比进入短。
- move：cubic-bezier(.2,0,.2,1)，用于选中底板与有限位置变化。
- spring：只用于拖动释放或被打断后的续接。若选择 Motion，原型起点可用 mass=1、stiffness=400、damping=40，目标无明显弹跳；opacity 仍用短 tween。参数只是起点，不照搬为另一库的 tension/friction。
- 距离规则：局部 ≤8px 用 120–160ms；短侧栏/面板用 180–220ms；手机跨较大距离最多 240ms 的普通转场。释放 spring 自然收敛，不同时指定固定 duration，也不承诺所有 spring 都在 240ms 内结束。
- 首次渲染直接到稳定状态，不全页 stagger；快速打开/关闭要改变当前目标，不重建“从屏外开始”的动画。

### 5.2 七类高级交互的适用性

| 模式 | Orbit 适用位置 / 当前具备情况 | 收益 | 限制与复杂度 |
| --- | --- | --- | --- |
| 跟手 / 预测性交互 | 模式底板、手机面板；目前无连续拖动实现 | 操作与画面同步，关闭前看见后方内容 | 中；不用 spring 追手导致滞后，不劫持系统返回 |
| 提交前取消 | 面板关闭预览、模式切换；目前主要点击即变 | 可以拖回、松手取消，减少误操作 | 中；区分视觉预览值与正式偏好；日程写入不能靠释放阈值确认 |
| 局部过渡 | 请求标签、附件、动作结果；已有部分 opacity 基础 | 降低跳变，保留阅读锚点 | 低；不要整个卡片交叉淡出导致重叠、不可点或难读 |
| 方向锁 | 双选 x，面板把手 y；当前没有自定义连续轴锁 | 避免轻微斜移误切换 | 中；触控阈值与鼠标分别验证，识别意图前不吞滚动 |
| 可中断 | Panel 开关、释放、局部标记；目前 CSS 可反转部分属性，条件挂载难保持当前位置 | 快速操作无需等动画完成 | 中；存在状态与手势状态同步，取消旧动画回调，不让旧闭合事件卸载已重新打开的层 |
| 结果 / 目的地预览 | 模型选择、面板下方内容；日历落点只列未来候选 | 操作前知道结果 | 拖移数据高；日历预览需显示时间/冲突，失败不得假装已保存；知识正文拖改不适用 |
| 边界阻力 | 面板把手和有限滑块；当前没有 rubber band | 给范围边界反馈 | 中；小范围压缩 12–24px 为原型起点，不实现第二套全页回弹，不碰普通文档滚动 |

手势规则的原型起点：意图阈值约 8–12px，轴向优势约 1.3–1.5 倍，确认后锁方向。滑块区域允许 pan-y；面板以把手启动，内部保持原生滚动与选择文字。关闭判定可先试位移约 25–33% 或明确释放速度，但必须经真机验证；不把该判定用于执行正式业务。

必须处理 pointercancel、lostpointercapture、窗口改变、页面隐藏和 unmount；回到已提交的状态，不保存半途预览值。再次接触正在释放的元素时，从当下位置接管；禁用的服务不能被滑动选中。点击、键盘和关闭按钮始终可用。

### 5.3 生命周期与业务状态

面板视觉状态建议明确区分 closed / opening / open / closing / dragging / settling。业务状态沿现有服务端枚举，不能为了动画改成固定轮播：

- Pending：可编辑、可取消；Confirmed 表示用户提交/服务器确认的事实，不是计时结束。
- Executing：真实请求或事件表明执行中，局部动作 busy；能取消的任务仍提供取消。
- Success / Failed / partially_completed：由接口和事件决定；失败保持内容与恢复入口。
- Completed：正式终态摘要。提醒已处理后不再显示“完成 / 15 分钟后 / 明天”；已失效显示失效原因。

“已取消请求”不保证已执行的业务被回滚；没有撤销能力就不能设计成可撤回成功。按现有合同解释可取消范围。

退出生命周期优先沿组件库；手写 CSS 可保留 presence 到 transitionend / animationend，但需过滤目标/属性、取消旧事件、处理减动无事件和卸载清理。兜底定时器只负责清理视觉层，不能保存数据、确认日程、完成请求或阻止输入。

CSS 的 transform、JS 拖动、Motion layout 不同时写同一个节点的 transform；必要时分离定位外层与内容内层。不得对整段正文做 scale 修正，避免文字变形。

### 5.4 Reduced Motion 与性能

- 保留现有 CSS 媒体查询，并补 JS 滚动与可能的手势释放判断；系统偏好变化后立即生效。
- 减动模式取消位移、spring、循环、自动 smooth 和布局重排动画；保留文字、选中、结果、错误和焦点。跟手可提供直接位置反馈，释放立即吸附或提供点击替代。
- 未来若引入 Motion，显式配置 reducedMotion="user"，不能依赖默认值；局部状态 opacity 是否保留由本系统规则决定。[MotionConfig 官方说明](https://motion.dev/docs/react-motion-config)
- 优先 transform / opacity；少量颜色变化可接受。移除 loading 中循环 box-shadow 的需求，避免动画大 blur / 阴影。
- 手势每帧不重渲染整个聊天树；位置更新可用 ref / CSS variable 或 motion value。测量批量进行，避免每帧交替读布局再写样式。
- 不常驻给全部卡片加 will-change；仅在必要的拖动/过渡层临时使用并清理。
- 长内容和真实慢设备用录制/性能面板测量，再判定是否掉帧；源码里的动画数量不等于性能结论。

### 5.5 不应加入动画的位置

1. 每次轮询回填、恢复历史消息和打开旧对话，不重新让所有气泡进场。
2. 模型逐字输出、阅读正文、代码、数学公式和长表格，不做打字机、数字滚动或整区 layout 动画。
3. 普通路由跳转、主题切换、所有卡片 Hover，不做全屏飞行、缩放背景或大幅升起。
4. 保存/确认按钮不等动画完才请求；错误不 shake；成功不彩纸、发光、弹跳。
5. 无真实进度的 Thinking、解析、研究不做百分比，也不拟人化宣称模型情绪。
6. 正常文档滚动、系统边缘返回、触控板滚动不加自定义橡皮筋或全屏方向锁。
7. 账号授权、危险操作、备份恢复等流程不做诱导用户继续的奖励式动画。
8. 空态、所有列表首屏、挂载工具入口不统一 stagger。独立工具内部已有目的明确的动画不因此删除，需按工具用途另审。

### 关于截图中的 timeout

signal timed out 表示某次等待超过前端设定的时间后被中止。当前聊天状态接口和 ChatGPT 模型目录读取都使用 20 秒 AbortSignal.timeout；单凭截图不能确定具体哪一请求、后端是否已继续执行，也不能判定为模型故障。

应区分：状态刷新超时→“状态刷新超时，正在重新连接”；消息提交超时→先按已有 requestId 核对是否接收，避免重发；工具失败→对应任务中的具体恢复提示。恢复成功后清理对应旧错误，而不是长期保留整行红条。截图中的“地点搜索响应结构异常”是另一项天气服务错误，本次 UI 方案不算已修复天气服务。
