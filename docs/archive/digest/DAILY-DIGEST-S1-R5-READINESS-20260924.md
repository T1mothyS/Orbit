## 上线候选与放行条件

当前仅**隔离 Shadow 的继续观察**可作为候选；正式 V2.5、邮件投递与第二阶段均未放行。按最小后续工作排列：

1. **真实日期与内容**：保留每日独立审计，补足至少 5 个不同真实日期；逐日记录实际输入、遗漏修订、证据时间、图像类型、耗时和通知；跨期 OAuth 成功不能代替多日稳定。现有跟进任务继续执行本范围，不在本卡手动凑日期。
2. **个人输入与状态**：在明确允许的测试数据边界内补齐必要日程/关注项，对同一时点旧 V2 逐项核对；修复 `not_configured` 空态，并对“确实无未读”和“读取失败”分别验收。
3. **媒体与恢复**：真实 Shadow 若选择已获逐图许可的图片，核对网页中照片及署名；`tmp/` 七日生命周期要纳入历史预览策略。隔离测试 CDN 域名存在后，再只用新建测试 URL 验证缓存清除；正式下架须先审计共享引用、留备份并处理正文引用。
4. **正式候选闸门**：在前三项收口后重新核对当前分支/版本、完整测试与构建、生产媒体域名、配置和备份回滚。正式 Work 切换、Git push/Release、服务器部署分别授权并分层验收；真实测试发信另行授权，记录 SMTP 接受与桌面/手机收件箱结果，不以队列状态代替送达。

本卡只形成证据汇总和候选清单，没有改变运行代码、隔离服务配置、测试 R2 对象、正式任务或用户数据。后续的实现和外部动作按对应卡片与授权执行。
