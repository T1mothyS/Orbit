本文的“旧版”指本次三来源改造前的 Cloud 日报；“新版”指当前 0.50.3-261006.1722 的测试版本。Shadow 指隔离测试日报：保存供阅读，不发信。本次盘点不执行部署或任务切换。

“能连 OpenAI”为何还不够？

当时常驻代理只把 OpenAI 请求送往代理出口，图片域名仍走直连；日报下载器也没有接入这个代理。另一个图片转发入口返回 403，具体授权原因尚未确认。

把已审核图片请求临时送往现有代理出口后，服务器七张全部下载成功。网络能力存在，缺的是常驻分流和应用接线。

下一步应该解决什么？

选定一条正式取图路线，让日报下载器每次都能使用，并用新的图片 URL验证。优先评估已证明可用的服务器代理路线。

还要验证 Work 能为新新闻选出贴题、可用的素材，进入现有审核规则。不能让每份日报都依赖一次人工搬运。

这批图是许可资料照，不是所有新闻发生现场的照片。此次成功没有涉及 Bloomberg 邮件正文图片提取；临时代理已清理，原生日报下载器的永久接线尚未实施。

03

后续按这四步推进

收敛到同一条上线链路。每一步产出明确证据，避免不断生成相同内容的测试稿。

  1. 把图片路线接成常驻流程

    下一项核心工程

    在服务器代理与现有转发入口之间选定主路线。推荐先沿已成功的代理方案做最小集成，保留来源、文件与安全检查，同时解决新素材如何进入可用范围。

    通过标准：Work 为新新闻选图，服务器自动取得新文件，转换、托管、正文显示正常；不靠本地下载、重复使用旧副本或逐次临时启动代理。取图失败的处理方式需明确，不能回到已被否定的模板图。

  2. 在另一个真实日期做一次合并验收

    内容 + 图片 + 真实输入

    先补最新稿的阅读评价，再换一个日期，以新候选、新文章和新图片测试。核对原任务实际 Prompt、Gmail 工具与正式账号个人输入；无需再次填写已有配置。

    通过标准：关注项有可读事实与参考链接，各项覆盖状态真实；来源缺失能回到搜索；主新闻、深读、拓展阅读和照片实际阅读通过。一次记录耗时、搜索量与失败，不另外拆成多轮重复测试。现有日程或邮件为空时，须确认是实际空值。

  3. 受控部署，并更新原来的正式任务

    后续授权后执行

    备份旧配置与 Prompt，部署冻结版本，仅为目标账号开启来源能力，更新原有任务。必要时刷新连接器工具目录，核对实际可见工具。

    回退方式：关闭来源能力并恢复旧 Prompt；代码保留回退版本，历史日报继续可读。生产部署、正式任务修改、GitHub push 与真实发信按各自授权执行，不新建第二个日报定时任务。

  4. 观察一次自然触发

    自动日报闭环

    让原任务按时间自行运行，核对读取、选题、取图、发布和是否重复执行。若正式交付包含邮件，再按授权检查邮件客户端与收件箱。

    通过标准：自然运行生成正确的新日报；邮件需要确认实际到达。保存成功、排队成功或 SMTP 接受，只证明对应环节。这一轮之后仍需短期观察来源与代理稳定性。

04

必须做、可省掉、可延后

上线前保留

  • 常驻图片路线与新图验证它直接决定明天是否仍要人工搬图。
  • 另一个真实日期用于排除只在同一批邮件和七张旧图上成功。
  • 正式账号输入与原任务核对测试账号空日程、空邮件，不能当成完整验收。
  • 实际阅读与最小回退检查看新稿的图文效果；确认旧 Prompt、配置和代码可恢复。无新代码时不机械重跑全套检查。

可以停止或合并

  • 反复复刻同一七张照片定位问题时有用，如今已证实服务器可下载。下一轮应换新素材。
  • 同时修代理和 Worker选择一条可用主路线即可；另一条不必成为并行上线条件。
  • 继续批量生成旧模板图用户已明确否定，不再用“每条有图”代替图片质量。
  • 为了上线增加队列或新调度首版没有必要；复用原任务、现有快照和托管即可。

可在上线后观察或后续做

  • 等待 Polymarket 新邮件不应单独卡住全体来源上线。无新邮件如实记录，搜索补漏；其恢复成功另验。
  • 证明已经省搜索成本目前没有旧流程对照。先记真实用量，积累后再比较，不以“省钱”包装现状。
  • 邮件原始 HTML、私有图片与市场 API属于第二阶段。当前内容与许可资料照已能走现有路径。
  • V3、向量库与完整投资研究不把其他路线全部变成本次前置条件。每日关注先给可靠事实，研究不充分如实说明。

“可省掉”是本次盘点的收敛建议，并未自动修改已有发布规则。Polymarket 暂时空缺可不阻断整体上线，但不能因此声称其新一期或概率链路已验收。

05

距离上线还有多远

剩余路径：一项核心工程，一次跨日验收，一次受控切换，一次自然运行。

手动测试版已经可以阅读。要成为每天自动生成的正式日报，下面四个环节还必须闭合；其中工程工作主要集中在第一项。

取新图自动化代理接线、素材选取和失败处理
跨日验收新内容、新图片、真实个人输入与实读
正式切换获得相应授权，部署并改原任务
自然运行确认到点能产出，按范围验证邮件

时间边界：至少还要覆盖一个不同的真实日期，再观察一次自然触发。若新图路线与正式 Gmail 调用顺利，不需要重做主体架构；若它们失败，需要先排障，当前证据不足以给出可靠的固定天数。

建议的下一项工作：先把服务器取图接成常驻流程，并用一组新 URL 验证。Polymarket 来信、成本对比和第二阶段功能不应拖住这一步。

生产切换完成即可说“新版代码与任务已上线”；经过一次自然触发，才有证据说“自动流程已跑通”。长期稳定性需要后续观察，不能由一次成功保证。
