## 滚动维护流程

日常任务仍向本地 CONTINUOUS-REQUIREMENTS.md 末尾追加，记录是审计流水，不是主要上下文。任务结束运行 `npm run history:check`：只读取小状态文件、文件大小和精简 CHANGELOG，不读取全部流水。换月、首次建档或活跃流水超过 1MiB 且又增长至少 64KiB 时才建议扫描；没有可迁移整月时不反复拆卷。

`npm run history:archive` 默认预览，`npm run history:archive -- --apply` 才实施。活跃流水至少保留最近 30 天，仅移动完全早于窗口的整月，通常保留约 30–60 天。月卷在忽略的 .local-docs/continuous/，原文备份、校验清单和小状态在忽略的 .local-docs/history/；这些私人文件不能加入 Git、发布包、报告正文或外部上传。月卷按原始字节与顺序保存，保留混合换行及同日无时间的原相对顺序。

CHANGELOG 通常保留最近 20 条完整版本，可阶段内增长至 24 条；达到 25 条时批量迁移至 changelog/ 的当月归档卷。旧阶段短版本、摘要、顺序与日期原样保留，只修相对链接，不自动补造日期或排序。TASKS/TEST-MATRIX 的阶段内容由 Agent 核对完成条件后迁移；脚本不根据年龄自动关闭任务。每个有日期的全量封存必须注明原基线和适用边界，不覆盖已有卷。

实际更新前完整备份原文件，验证字节重建/链接往返，再检查源 hash 没有发生外部变化；逐文件原子替换，保留一次 pending.json 事务记录阻止并发归档。备份及 completed.json 是校验依据，不自动删除。失败保留现场，`npm run history:archive -- --recover` 按原 hash 回滚整批；任何文件被外部修改则拒绝覆盖，先人工核对。不要直接删除 pending.json 或在任务中途迁移尚未完成的执行记录。

重复执行应显示空 files；`--force-scan` 仅用于校验既有月卷或显式复查，不放宽保留窗口。归档后运行 `npm run docs:check`，帮助输入改变时重建索引并执行产品帮助测试；机器评测输入和绑定历史提交的 project-evolution 路径保持不变。恢复不回滚用户随后新增的流水，冲突时停止复核。
