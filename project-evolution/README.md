# 项目成长数据与维护

- Status: FEATURE / CONTRACT
- Scope: `/project`、受登录保护的项目级历史数据、生成和校验流程。
- Last verified: 首版实现；具体本地验收记录见文档末尾，不代表生产状态。
- Authority: 指定提交的源码与 Git 对象为事实来源；`curated.json` 维护叙事和架构摘要；`generated.json` 为服务端交付物。
- Update trigger: 新里程碑、结构变化、历史更正、统计口径或页面合同变化。
- Supersedes: 无。
- Do not use for: 证明当前生产版本、真实邮件到达或设备同步验收。

## 阅读与访问

头像菜单提供“项目成长”“Tools 工具中心”和“使用统计”；原“挂载工具”设置分区保留。设置顶部不再提供重复快捷入口，成长页与个人统计页在内容左上角统一提供无文字箭头返回今日，其他入口从顶栏导航与头像菜单切换，周报配置仍在设置的通知分区。个人统计仍使用兼容的 `/project?view=statistics`，不读取共享项目成长 JSON。项目成长不加入主业务导航。
所有有效登录账号访问同一份项目事实，不查询账号业务数据。`GET /api/project-evolution` 使用现有 Bearer 认证，失效/禁用账号拒绝访问，返回 `Cache-Control: private, no-store`。缺失、损坏或不符合模型的数据返回 503，不泄露文件路径。

`/project` 使用全宽舞台：紧凑页头、单条数轴、播放控制、架构与当前故事；趋势、测试及工程证据默认收起。数轴按里程碑先后等距排列，不代表天数；全部节点支持悬停/焦点提示、点击和键盘选择，同日记录逐个可达。手动选择进入暂停的完整历程，前后步骤按全部里程碑移动；默认五站精选演示及完整历程各播放一次后停止，未新增快照的里程碑明确显示架构沿用，不重复新增动画。精选比较相邻精选站，完整历程比较相邻里程碑。旧 `view=growth|architecture` 均定位统一舞台，`milestone=<id>`、非法选择回退、登录目标与前进后退保留。自动推进只调整数轴横向可视范围，不写URL、抢焦点或滚动正文；视口外/后台暂停并保存剩余停留时间。减少动态效果默认最新静态记录，显式播放仅切换历史。页面和CSS仍懒加载，JSON不进入Web bundle。设置草稿与离开保护沿用原合同。

桌面宽度至少1024px且窗口高度至少800px时，默认简明舞台适配首屏；手机/平板纵向排列。左右列各按自身内容高度，展开说明不拉长左图；长标题、低高度、模块及证据均允许整页增长。成长保持全宽；个人报告使用现有PageFrame作为整页滚动所有者，内层内容复用 `--orbit-content-max` 居中限宽，边距仍响应滚轮，不新建内层竖滚。

演示倍速为0.5×/1×/1.5×/2×，默认1×；节点停留按相同倍率推进，节点/连线/文字入场通过浏览器Animation播放速率同步，不重建时间轴。中途切速保留已走过的基础时间，暂停/后台/离屏保留剩余时间；重播才重置。减少动态效果时停用入场动画，显式播放的历史切换仍支持倍速。

完整图根据容器宽度把四类节点投影到紧凑分组列，历史JSON与坐标不变、所有节点和真实边保留。局部画布用变换平移/缩放，不增加竖向滚动容器：桌面空白拖动、区域内滚轮按指针中心缩放；区域外继续滚动页面。缩放范围25%–250%，初始适配保留至少90%比例以保证文字可读，密集或窄屏因此可能需要平移；“适应画布”可按两维显示全貌。保留键盘方向键、＋/−、Home及简洁按钮；移动端默认单指浏览，明确进入操作画布后单指平移/双指缩放，再完成恢复浏览。简明/完整切换与清除节点聚焦互相独立。聚合连接汇总原始边的各类变化，含新增为绿、否则变化为橙、否则移除为红虚线；混合数量完整列出，聚焦不覆盖变化颜色。

## 事实与边界

- 首批 15 个里程碑来自当前基线可达历史，起始日期是最早收录 Git 记录，不宣称项目创立日期。
- `commit` 是证据所在完整哈希；版本来自该提交的 `package.json`。tag 独立列出，冲突标注，不把相邻 tag 推断为所属发行。早期 `1.0.0` 原样保留，后续 `0.x` 并非数据错误。
- 日期为committer时间，页面以 `Asia/Hong_Kong` 展示。数轴按里程碑顺序等距排布，不表示时间间隔长度；当前数据没有分支归属，不将能力分类画为Git分支。
- Git 只生成元数据和数字，不导出提交正文、作者或完整文件清单。摘要与证据路径必须审核，不复制本机日志、用户内容、凭据或服务器地址。
- 测试数量取该提交内的验证文档，`null` 表示缺失。首批仅两条可靠本地测试计数，使用离散证据列表而非完整横轴曲线；套件范围不同的数字不能直接比较质量。
- 架构是职责级概览，不是自动抽取的调用图。“最早可证实”指最早收录快照，不代表精确引入日期；结构存在不等于外部服务或设备验收成功。
- 阶段是叙事分类，时期有重叠；领域采用稳定 ID，不按按钮或文件数推断功能。

## 统计规则 source-nonempty-v1

跟踪文件数取指定提交 `git ls-tree -r` 的全部文件条目。源码非空行只计算 `src/`、`server/`、`electron/`、`scripts/` 内 `.ts .tsx .js .jsx .mjs .cjs .css .html .ps1`，包含注释与测试。

排除 `node_modules`、`dist`、`build`、`coverage`、`generated`、`vendor`、`data`、`backup` 路径段、`.min.` 文件、旧版构建目录 `server/public/`，以及名称包含 `project-evolution` 或 `ProjectEvolution` 的本功能文件；锁文件、二进制、文档和历史数据不计入源码。更改口径需升级规则 ID，不静默改变数字含义。

提交总数使用 `git rev-list --count <commit>`。源码批量读取 Git blobs，不 checkout，不读取当前工作区对应源码。能力领域数取显式领域集合；图表 X 轴为里程碑顺序，Y 轴各自归一化，精确值在数据表中。

## 更新流程

```powershell
npm run evolution:generate
npm run evolution:check
npm run evolution:history
```

先把已提交并核实的完整哈希、摘要、领域和快照引用写入 `curated.json`，更新 `baseline` 到覆盖这些提交的已提交基线，再生成。普通构建只校验已有文件，不修改历史或要求 Git；完整历史校验需要完整对象和 tag，CI 使用完整 checkout。

生成器不自动选取 HEAD，不覆盖摘要，不引用自身将产生的 commit。同样输入生成同样 JSON，无运行时间戳。应用版本与收录截止点分别展示，当前功能自身可在后续批次收录。tag 发生变化时完整校验失败，需核实后显式再生成。

只有职责或连接变化才新增架构快照，其余里程碑可引用过去快照。节点/边 ID 和位置稳定，名称与说明保存在各个快照中，不从最新内容反向覆盖历史。同 ID 内容变化判为“变化”，旧快照独有节点在比较时显示“移除”。更正历史需在提交说明与本文件末尾记录理由。

模型拒绝未知字段、重复 ID、缺失或未来引用、无效指标、无证据测试数、位置漂移和悬空连线；完整历史校验进一步核对可达提交、源码路径、版本、tag、指标与测试计数文档。

## 验证与发布

- `server/project-evolution.test.ts`：模型、统计、结构差异、现有认证的失效/禁用账号和损坏资源。
- `node scripts/project-evolution-browser-smoke.cjs`：已有 Playwright 和 Edge；可用 `PLAYWRIGHT_MODULE` 指向现有安装，不引入项目依赖。使用 loopback、合成账号/API，截图及报告写系统临时目录。
- 浏览器覆盖四尺寸明暗主题、入口、深链接、前进后退、登录回跳、空/错误/慢加载、长文本与焦点；真实认证由独立 HTTP 测试覆盖。
- 发布包必须保留 `project-evolution/generated.json` 及正常服务端和共享类型源码；只上传 `dist/` 不足以提供接口，JSON 不挂静态目录。缺失返回 503，补齐同版资源或整体回滚，无数据库迁移。
- 生产发布仍需独立授权，遵循预构建 runbook；本地检查不代表生产验收。
